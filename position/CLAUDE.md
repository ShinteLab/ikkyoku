## `position` パッケージ（画像を知らない層）

局面矯正（Phase 3）と検討ツリー（Phase 5）は **`ikkyoku/position`** に置く。
**別モジュールには切らない**（`ikkyoku → core` の依存で足りる）。

**`recognize` には入れない。** あちらは画像を知っている層で、`position` が扱うのは
**画像を一切持たない「とある局面」**。境界は「`recognize` が返した盤面を受け取ったら、
そこから先は画像を参照しない」。撮った PNG はディスクに残っていればよく、
学習への還元でパスが要るのも UI の端（`CaptureResult` が既に持っている）で済む。
**`position` の型に画像やその座標系を持たせないこと。**

## 何を残すのか

| 情報 | どこが持つ | 注意 |
|---|---|---|
| 誰と誰の対局か・棋戦名・日時 | **`core/kifu` の `Document`**（`Black`/`White`/`Event`/`StartedAt`…） | **ikkyoku で対局者フィールドを定義し直さない** |
| 何手目か・手番 | **SFEN**（手番と手数を含む） | 局面と別に持たない。「手番は局面から決まらない」は**盤の絵からは**決まらないという意味で、確定した局面には入っている |
| そこから何を選んだか（分岐） | **`core/kifu` の分岐ツリー拡張**（未実装） | 今の `kifu.Document` は `Moves []Move` の本譜一直線。**木の形は core で決める**（kicho の保存形式に波及するため）。入るまでは `position` に薄く仮置きする |

## 入っているもの（`board.go` / `position.go`）

継ぎ目は **`recognize.Board.SFEN` → `position.FromBoardSFEN`**。ここから先は画像を見ない。

| 型 / 関数 | 役割 |
|---|---|
| `Cell` | 1 マス。`NewCell(piece, black, promoted)` で作る。**ゼロ値が空マス** |
| `Board` | 9x9。`At` / `Set`（訂正の入口）/ `SFEN()` / `Inspect(checks)` / `Clone()` |
| `Position` | 盤面 + `Turn` + `MoveNumber` + 駒台の割り振り。`SFEN()` / `Warnings()` / `Violations()` |
| `Stock` / `Inventory()` | **「存在するはずの駒」の在庫**（`edit.go`）。残り = 上限 − 盤上で、**負なら過剰**。訂正 UI の駒箱はこれを並べる |
| `Place` / `Remove` / `Move` / `TogglePromoted` / `FlipSide` | 訂正の操作（`edit.go`）。**合法性は問わない** |
| `MateProblem` / `NormalizeMateHands` | **詰将棋か**（2026-09-12）。⚠️ **`Warnings()` が「攻方の玉がありません」を言わなくなる**（詰将棋では正しい姿。**玉方の玉が無いときは言う**）。余りは**全部が玉方（後手）の持駒**で、保つ約束は **玉方 = 逆算した合計 − 攻方**。⚠️ **駒台に実体として載せる**（計算で見せるだけだと `FromHand` が掴めない）・⚠️ **1 操作ごとに `NormalizeMateHands` を呼ぶ**（それが「属性」の実装）・⚠️ **`HandsFixed` とは排他**・⚠️ **`Clone()` で写すこと** |
| `Game` | 対局の素性。**`core/kifu.Document` のエイリアス**（対局者を定義し直さない） |
| `Connect` / `ConnectSFEN` | **盤面の差分を合法手の経路で手順に復元する**（`connect.go`。Phase 6）。確定局面と**盤面だけ**を受け、そこに至る手順を探す。⚠️ **一意でなければ `Moves` は空**（下記） |
| `FromKIF` / `FromFullSFEN` | **棋譜・完全形 SFEN の取り込み**（`kifu.go`）。⚠️ `FromBoardSFEN`（認識の入口。未決だらけ）とは別物で、こちらは**手番も持ち駒も決まった局面**を返す |

⚠️ **手合割（駒落ち）と詰将棋の全体像はスキル `ikkyoku-handicap-mate`。**
ここにあるのは**この層の制約**（`HandsFixed` / `MateProblem` / `Clone` で写す）。

**壊さないこと（テストで固定してある）**:

- ⚠️ **`MateProblem`（詰将棋）も落とさない**（2026-09-12）。⚠️ **`Clone()` で
  写すこと** —— 落とすと**1 手進めた瞬間に余りが未決に戻り**、SFEN が組み上がら
  なくなる（`HandsFixed` を落としたときと同じ壊れ方）。⚠️ **`HandsFixed` とは排他**で、
  排他を保つのは `PositionService`（型としては 2 つの bool）
- ⚠️ **`HandsFixed` を落とさない**（2026-08-12）。「駒台は書いてあるとおりで、
  盤上から逆算しない」の印で、`FromFullSFEN`（＝ KIF の初期局面）が立てる。
  **駒落ちは盤にも駒台にも存在しない駒がある局面**なので、逆算すると
  「駒台にあるはず」の未決が消えず、**`SFEN()` が永久に組み上がらない**
  （二枚落ちの棋譜が 1 手も進まない。実際に踏んだ）。⚠️ **`Clone()` でも写すこと** ——
  落とすと 1 手進めた瞬間に逆算が復活して同じことが起きる。
  **画像から作った局面では常に false**（あちらは逆算が訂正 UI の拠り所）。
  ⚠️ **訂正タブから人が立てられるようになった**（2026-09-12。`SetHandsFixed`）——
  **駒落ち・詰将棋を撮ったとき、逆算したままでは確定できない**ため。
  そのとき行き場の無くなった枚数は `Stock.Unused`（**この対局で使わない駒**）に回る。
  ⚠️ **`Unassigned` と `Unused` は同時に立たない**（逆算するかしないかの裏表）。
  ⚠️ **`Unused` は確定を止めない** —— 使わない駒があること自体が正常

- **`Cell` のフィールドは非公開のまま。** 公開すると `Cell{}` が「先手の歩」になる
  （`sfen.Pawn == 0`）。ゼロ値は空マスでなければならない
- **駒台は「合計」を持たず「先後それぞれに何枚割り振ったか」だけを持つ**（`SetHand`）。
  合計は盤上の駒数からの逆算（`core/sfen`）で、訂正のたびに変わる。
  **残りを片側に寄せない**（未決は未決のまま `Unassigned()` に残る）
- ⚠️ **駒台の枚数を逆算した合計で丸めない**（2026-08-08 に直した）。
  以前は `SetHand` が合計超過をエラーにし、`Hands()` が超えたぶんを切り詰めていたが、
  そのせいで**既に足りている駒を駒台に載せられなかった**（載せても表示に出ないので、
  駒台から先後を決める操作が途中で詰む）。**`Place` が在庫を見ないのと同じ**で、
  多すぎることは `Warnings()` に出すだけにする（設計原則3・4）。
  盤上だけの超過は `core/sfen` が言うので、`position` が足すのは
  **「盤上 + 駒台」で初めて超えたぶん**だけ（`handWarnings`）
- ⚠️ **「足りない駒」も警告に出す**（2026-08-18。`missingWarnings`）。盤にも駒台にも
  無い駒は、駒数保存則からすると**どちらかの駒台にあるはず**なのに置き場所が
  決まっていない状態で、**そのあいだ局面は確定しない**（`SFEN()` が組み上がらない）。
  **過剰だけを言って不足を黙っていると、何をすれば確定するのかが警告から読めない。**
  - ⚠️ **`HandsFixed` のときは言わない** —— 駒台が書いてある局面（KIF・完全形 SFEN）
    では逆算しないので未決が無く、**駒落ちは盤にも駒台にも無い駒があって正常**
    （言うと毎回警告が出る）
  - ⚠️ **玉は数えない**（駒台に載らないので「足りない」は盤の枚数の話になり、
    それは `core/sfen` の `CheckKing` が既に言っている）
  - ⚠️ **これも警告どまり**（設計原則3）。**確定の可否は今までどおり
    `SFEN()` が組み上がるかだけ**で、警告の件数では判断しない
- **手番が未決、または駒台の先後が未決なら `SFEN()` はエラー。** 盤面だけ要るなら
  `BoardSFEN()`。ここで先手に倒すと、決めていないことが決まったことになる（設計原則5）。
  手数だけは 0（不明）でも `1` と書く（SFEN の書式が必須にしているだけで、
  局面の解釈を変えないため）
- **検証を自前で書かない。** 二歩も行き所のない駒も駒数上限も `core/sfen` の `Inspect`。
  `Warnings()` は直している最中に当然出るもので、**エラーとして扱わない**（設計原則3）

### 盤面の差分から手順を復元する（`Connect`。Phase 6）

**中継を撮って認識すると「盤面」しか分からない。** そこから「本譜の先端から何手
進んだのか」を割り出すのがここ。`legal.Moves` + `ApplyMove` で反復深化する。

**これ 1 つで 4 つ片付く**（だから撮るだけで追える）:

| 画像から決まらないもの | なぜ要らなくなるか |
|---|---|
| CM 中に進んだ手 | 1 手で繋がらなければ深さを上げる |
| 認識の誤り | **合法手で到達できない盤面は落ちる** |
| 手番 | 根で 1 回決まっていれば、以後は**経路の偶奇**で決まる |
| 駒台の先後 | `ApplyMove` が取った駒を指した側に載せる（**逆算に戻らない**） |

**壊さないこと（テストで固定してある）**:

- ⚠️ **一意でなければ `Moves` を空にする。** `Solutions[0]` を選ばせないための形。
  順番が決められないのに 1 本選ぶと、**空想の手順が「実際に現れた指し手」として
  棋譜に残る**（`TODO.md`「本譜のロック」が一番避けたい壊れ方）。**選ぶのは人**
- ⚠️ **`MaxWaste`（食い違いを埋めない手の上限）を外さないこと**（2026-09-14）。
  深さ 4 まで素直に探すと、**相手が往復して戻る**手順でほとんどの盤面に辿り着く
  —— 歩が一気に 2 マス進んだ盤面が `7g7f 7a6b 7f7e 6b7a` で「繋がった」。
  **これを外すと「合法手で到達できない盤面は落ちる」が成り立たない**（＝ 認識の
  誤りを落とす働きが消える）。既定 2 は「**同じ駒を 2 回動かす**のは普通（▲2六歩
  ▲2五歩）／**往復して戻る偽の手順は 3 以上かかる**」の間に引いた線
- ⚠️ **`StopBudget` と `StopUnreachable` を混ぜないこと。** 前者は「探し切れなかった」
  （深さを上げて再挑戦してよい）、後者は「探し切って無かった」（認識の誤りとして
  捨てる）。**次にすることが違う**
- ⚠️ **手番が逆でも「繋がらない」とは限らない**（2026-09-14 に実測）。1 手の深さでは
  必ず落ちるが、深く探せば「相手が指して自分が往復した」手順が出る。
  **「繋がらないこと」を手番の検算にしないこと** —— 言えるのは
  **一意にならない ＝ 断定して据えることはない**まで。
  ⚠️ **逆の手番で勝手に試し直さないこと**（設計原則5）
- ⚠️ **`ConnectSFEN` は読めなかった盤面を断る。** `FromSFEN` は壊れた盤面でも読めた分を
  返す（訂正 UI のための仕様）が、**読めなかったマスは空マスに見える**ので差分が
  嘘になり、「駒が消えた」経路を探しに行く
- ⚠️ **同じ局面へ戻る往復（4 手など）は差分 0 に見えるので消える。** これは仕様。
  直そうとすると履歴に依存した推測が入る（設計原則1）。**撮る間隔を詰めて途中を
  拾うのが手当て**であって、ここで前の盤面を覚えることではない
- ⚠️ **下界（`bound`）は安い足切りであって、正しさの砦ではない。** 駒が**何枚も**
  湧いた盤面は `legal.Moves` を 1 回も呼ばずに `StopTooFar` で落ちるが、
  **1 枚だけなら落ちない**（「1 回打てば届く」ので）。あちらは合法手生成が
  「その駒は持っていない」と言って落とす

**費用**（実測。⚠️ **これを前提に既定値を決めてある**）:
`legal.Moves` 1 回が **約 7µs**（`legal.BenchmarkMoves`）、`Connect` の深さ 4 が
**約 0.7ms**（`BenchmarkConnect`）。`MaxNodes` の既定 2 万は 0.14 秒ぶん。

### 本譜の先端（`Study.MainTip`）

**中継を追うときの繋ぎ先。** ⚠️ **`Current()` ではない** —— ユーザーが枝の途中を
読んでいるのは普通で、そこを繋ぎ先にすると**検討の枝に中継の手が生える**。
⚠️ **`MainLine` と同じところで止まる**（「分岐にする」で下げた手から先は本譜ではない）。
⚠️ **見ている場所は動かさない**（読むだけ）。

### 手数と手番は互いを縛る

平手なら **手数が奇数 = 先手番**（SFEN の手数は「これから指す手の番号」）。
手数を入れれば手番は決まるので、入力の手間を減らせる。

⚠️ **SFEN の手数と棋譜の手数は 1 つずれる。** SFEN は**初期局面が 1**（まだ誰も指して
いない状態）だが、棋譜で言う「1 手目」は**初手を指した後**の局面を指す。UI に手数を
出し入れするときは、どちらの数え方で言っているのかを毎回確かめること
（`position.Position.MoveNumber` は SFEN の数え方）。

**懸念（未決）: ユーザが入れた手数は +1 して持つことになりそう。**
SFEN の `40` は「次が 40 手目」だが、**ユーザが「40」と入れるときは「40 手目を指した
後の盤面」を指していることが多い**（中継のテロップもそちら）。だとすると入力を
そのまま `MoveNumber` に入れるのは間違いで、`+1` して持つのが正しい。

- **手番の偶奇も逆になる。** SFEN では奇数が先手番だが、ユーザ入力の数え方では
  **偶数（＝偶数手目を指し終えた）が先手番**。取り違えると手番が 1 手ずれる
- **たぶん UI の文言で済む話。** 入力欄を「**次は x 手目**」と書けば、どちらの数え方かを
  聞くまでもなく決まる（内部の `MoveNumber` と一致する）。棋譜の数え方で入れさせるなら
  そのときだけ `+1` する
- **先手/後手の表記と手番のマークを出しておけば、取り違えても気づける。**
  手数と手番は互いを縛るので、片方の間違いはもう片方の見た目に出る
- **決めるのは実際に UI を作る段でよい**（この節はそのときに読み返すためのもの）

- 食い違っていても**警告どまりにする。エラーにしない**（設計原則3）
- ⚠️ **駒落ちでは逆**（上手＝後手が初手を指す）。手合割は `kifu.Document.Handicap` が持つが、
  今は `Game` を UI から埋めていないので、**当面は「奇数=先手番」を提案値として出すだけ**に
  留めて、決め打ちにしないこと
- ⚠️ **`w` + 手数 1（`... w - 1`）は正当な局面。** 駒落ちの初期局面がまさにこれ。
  **偶奇が合わないからといって弾いたり、手数を勝手に直したりしないこと**
  （平手だけを前提にした検証を書くとここで落ちる）


### Go 側の層（`position.Study` / `ikkyoku/legal`）

```
StudyService ──> position.Study ──> position.Position.ApplyMove   手を盤に反映する
                       └────────> ikkyoku/legal.Moves ──> engine  合法かどうかを言う
```

- **`position.Study` は「根 + 指した手の並び」を持つ。** 今の局面は毎回組み立て直す。
  ⚠️ **局面を単体で持たないこと** —— 手順とずれたときにどちらが本当か分からなくなる。
  この形にしてあるのは、**エンジンに渡すのがまさにこの形**（`position sfen <根> moves ...`）
  なのと、**戻る操作が並びを短くするだけで済む**（逆再生を書かなくてよい）から
- ⚠️ **これは設計原則1（履歴に依存しない）に反しない。** 根の 1 局面だけで解析は
  成立していて（手順が空でよい）、手順は**ユーザーが自分で伸ばしたもの**。
  中継を最初から観ていなくても、撮った 1 局面から手を進められる
- **合法性の判定は `ikkyoku/legal` だけ。** `position.ApplyMove` は「決まった手を
  盤に反映する」だけで合法性を見ない（**分けてあるので `position` が engine を
  知らずに済む**）。⚠️ **合法手生成が要るので `ikkyoku → engine` の Go 依存が戻った**が、
  **用途が違う**（手の検証であって解析ではない）。
  **解析をこちら経由に戻さないこと** —— 棋力の問題を設定の問題にした意味が無くなる
- ⚠️ **`legal.Moves` は panic を握る。** 訂正 UI は不正な局面も確定できるので、
  想定外の局面が来る。**アプリごと道連れにしないこと**（設計原則3）
- ⚠️ **合法手が出せなくても局面は返す**（`StudyState.LegalError`。エラーにしない）。
  手が指せなくなるだけで、盤も解析もそのまま使える。**理由は画面に出すこと** ——
  出さないと「駒を押しても光らない」の理由が分からない
- ⚠️ **手を足す口は 3 つ。「進むか」と「出所を残すか」で使い分ける**
  （`Play` / `AddLine` / `PlayLine`。2026-09-14 に 3 つめが入った）。

  | | 進むか | 印 | 誰が呼ぶか |
  |---|---|---|---|
  | `Play` | **進む** | `Hand`（人が指した） | 盤のクリック・`FromKIF` |
  | `AddLine` | **進まない** | `Sources`（エンジン） | 候補手の右クリック →「手順を追加」 |
  | `PlayLine` | **進む** | `Sources`（エンジン） | 候補手の右クリック →「手順を指す」 |

  ⚠️ **`PlayLine` の `head` は指し継ぐ列の 1 手目だけ真にすること。** 毎手立てると
  `Nodes` の字下げが 1 手ごとに 1 段増え、**40 手指させたら 40 段の階段**になる。
  ⚠️ **既にある手には立たない**（本譜の続きをなぞっただけで**実際に現れた指し手が
  変化に落ちる** —— `Branch` を黙って押すのと同じ）。
  ⚠️ **1 手目を頭にしてあるのは本譜を 1 手も動かさないため** —— エンジンが指した手は
  実際に現れた指し手ではないので、`AddLine` と同じ扱いにする
- ⚠️ **座標の読み替えは `legal` と `position/move.go` の 2 か所だけ。**
  `core/usi` の内部 x は**筋番号ではない**（`FormatSquare` が `10-x` を書くので
  7 筋は x=3）。x=1 が 9 筋で、`core/sfen` の file の数え方と一致する。
  **間違えると、見た目は動くのに 1 マスずれた手を指す**（テストで固定してある）

## テスト（`go test ./...`）
