# piecefont の AGENTS.md

**端末に入っているフォントから駒の字を焼く**（設定タブの「駒の字」）。
⚠️ **TTF を組み立てるコードはここに書かない**（`core/shogifont`）—— 字形の生成は
将棋の表示の**仕様**側。ここが持つのは「端末のどこにフォントがあるか」だけ。
⚠️ **焼いたものを書き出す口を持たない**（下記のライセンスの話）。

## 駒の字を端末のフォントから作る（**入っている**。2026-08-16）

**設定タブの「駒の字」。端末に入っているフォントから駒の 19 グリフだけを焼いて、
その端末の表示に使う。**

```
端末のフォント ──piecefont.List──> 一覧（駒の字が揃っているか）
        └──piecefont.Build──> core/shogifont.Build ──> 10KB の TTF
                                    └──> data URL ──> @font-face ──> --shogi-font
```

⚠️ **なぜこうなっているかを先に読むこと。** 同梱して配る駒フォントは
**派生物の作成と再配布を認めるライセンス**のものに限られる（`core/web/README.md`。
游明朝・どへた・桜鯰は実際に外している）。だが**自分の端末に入っているフォントを、
自分の端末で表示に使うのは再配布ではない。** そこだけを通す経路がこれ。

- ⚠️ **焼いた字を書き出す口を作らないこと**（Go 側にもフロントにも無い）。
  書き出せると「その端末で表示する」を越えてしまい、元フォントの条項が効く側の
  話になる。**ディスクにも残さない**（下記）
- ⚠️ **TTF を組み立てるコードを ikkyoku に書かないこと**（`core/shogifont`）。
  字形の生成は将棋の表示の**仕様**側なので core に一本化する。
  ikkyoku が持つのは「端末のどこにフォントがあるか」というアプリ側の話だけ
- ⚠️ **元フォントの権利表記を画面に出すこと**（`Face.Copyright` / `License`）。
  **何に由来する字なのかを利用者が判断できる**ようにするため。
  ⚠️ **空でも「制約が無い」ではない**ので、無いときに「自由に使えます」と書かない

### ⚠️ 焼いた TTF はディスクに残さない

**残す理由が無い**（10KB なので起動のたびに焼き直しても一瞬。実測で数十 ms）うえ、
残すと**元フォントを入れ替えたのに古い字で描く**という、画面からは気づけない事故が
起きる。使い回し（`FontService.baked`）の鍵に**更新時刻と大きさを入れてある**のも
同じ理由で、**入れ替えたら焼き直しになる。**

### 一覧は「全部出して印を付ける」

端末に入っているフォントの**大半は駒の字を持たない**（実測で 239 書体のうち
焼けるのは 85）。⚠️ **足りないものを一覧から消さないこと** —— 消すと
**探しているのか対象外なのかが画面から分からない。** 選べない見た目にして、
**何の字が足りないか**を出す（`Face.Missing`。要る字は `shogifont.Required()`）。

- **探すのは押したときだけ**（`FontService.Scan`）。実測で 190 ファイル・577MB を
  読んで 1 秒弱。**起動のたびに走らせる類の処理ではない**ので、フロントは待ちを出す
- ⚠️ **Windows はシステムとユーザーの 2 か所を見る**
  （`%SystemRoot%\Fonts` と `%LOCALAPPDATA%\Microsoft\Windows\Fonts`）。
  **後から入れたフォント（まさに駒に使いたいもの）はユーザー側に入る**
  （Windows 10 以降、管理者権限なしでインストールするとこちら）
- **絞り込みは手元でやる**（探し直さない）。「駒の字が揃うものだけ」の
  チェックは**既定で切**（＝全部出す）
- ⚠️ **名前は日本語名を優先する**（`core/shogifont` の `Face.LocalFamily`）。
  英語名だけだと「玉ねぎ楷書激無料版v7改」が
  `Tamanegi Kaisho Geki FreeVer 7` になり、**自分が入れたフォントだと分からない**。
  **ファイル名も出すこと** —— 同じ名前の書体が別のファイルにあることがあるうえ、
  日本語名を持たないフォントではファイル名が唯一の手掛かりになる
- ⚠️ **TTC は書体ごとに 1 行**（`msmincho.ttc` に MS 明朝と MS P明朝が同居している）。
  **登録の鍵はパスではなくパス + 書体番号。** 番号が落ちると**別の書体で焼く**

### 登録は複数・使うのは 1 つ

エンジンと同じ形の一覧（`Config.PieceFonts`）＋**今どれを使うか**（`Config.PieceFont`。
空なら同梱）。⚠️ **「使う」を行の中の印にしないこと**（エンジンの `Enabled` とは
性格が違う）—— 盤は 1 つしかなく駒の字も同時に 1 つしか使えないので、
**2 つに印が付いているという表せてはいけない状態**が作れてしまう。画面はラジオ。

- ⚠️ **family は登録ごとに違う名前**（`ikkyoku.PieceFontFamily` = `ShogiUser-<id>`）。
  **同梱の `ShogiSFEN` とも必ず違うこと** —— 同名で二重に登録すると
  どちらが当たるかがブラウザ任せになり、**同梱に戻せなくなる**
  （`core/web/README.md` の「family 名を揃えないこと」）
- ⚠️ **当て方は `--shogi-font` ただ 1 つ**（`:root` に入れる。`applyPieceFont`）。
  `<shogi-board>`（core/web）も、駒台の駒（`.stock-chip`）も、掴んだ駒の絵も、
  候補手の重ね表示（`.study-hint-piece`）も**全部この変数を見ている**。
  ⚠️ **要素ごとに `font-family: "ShogiSFEN"` を書かないこと** —— 1 か所でも
  直し忘れると、**そこだけ書体が食い違う**
- ⚠️ **焼けなくても同梱で描けること**（設計原則3）。フォントを消したり
  アンインストールしたりするのは普通に起きるので、**エラーにせず理由を出すだけ**
  （`FontState.Note`）。**登録も消さない** —— 入れ直せばそのまま戻る
- ⚠️ **一覧に無い ID を指しているときだけ同梱として返す**（`state`）。
  **登録が一覧にあるなら、焼けなくても選択は残すこと** ——
  同梱を選んでいるように見せると、どれを選んだのか分からなくなる
- **見本（`FontService.Preview`）は登録せずに焼く。** ⚠️ **family を毎回変えること**
  —— 同じ名前で焼き直すと、どちらが当たるかがブラウザ任せになって
  **前のフォントのままに見える**ことがある
- **登録したらそのまま使う状態にする**（`Add`）。登録する操作は「この字で見たい」
  なので、そのあともう一度選ばせるのは 1 手多い

### 駒の字の色と濃さ（2026-08-16）

**字の強いフォント（太い明朝・毛筆）は少し薄いほうが盤に映える。**
端末のフォントを選べるようにした以上、書体ごとに濃さを合わせたくなる。

```
Config.PieceColor + PieceOpacity ──PieceInk──> rgba(…) ──> --shogi-piece-color
      （設定は別々）                （1 つに合成）        （盤も自前の駒も同じ値）
```

- ⚠️ **画面に渡すのは 1 つの値**（`ikkyoku.PieceInk` が alpha 込みの色に合成する）。
  盤の中は SVG なので `fill-opacity` でも足りるが、**ikkyoku は HTML でも駒を描く**
  （駒台のチップ・掴んだ駒の絵）。そちらで濃さを別に当てると element の
  `opacity` になり、**駒の背景（木地）ごと透ける**
- **設定ファイルでは色と濃さを別に持つ**（色を変えても濃さが消えない）。
  ⚠️ **合成は `PieceInk` の 1 か所** —— フロントで組み立て直さないこと。
  引いている最中の見た目のために作り直すと、丸め方が食い違ったときに
  **「離した瞬間に色が飛ぶ」**という追いにくい壊れ方をする。
  代わりに**送るのを間引く**（`saveInkSoon`）
- ⚠️ **`core/web` 側にも口が要る**（`--shogi-piece-color`。2026-08-16 に足した）。
  シャドウ内の `text.piece { fill: … }` が外からの継承に勝つので、
  **カスタムプロパティでないと届かない**（`--shogi-font` と同じ）
- ⚠️ **既定は core/web の既定と同じ値にすること**（`DefaultPieceColor` = `#1a1a1a`）。
  食い違うと、**設定を触っていないのに駒の色が変わる**（変数を当てた瞬間に別の色になる）
- ⚠️ **範囲外を弾かずに丸める**（設計原則3）。読めない色は既定へ、
  薄すぎる濃さは `MinPieceOpacity`（0.2）へ。**0 まで許さない**のは、
  **駒が消えて盤が壊れたようにしか見えない**から（戻し方も分からなくなる）。
  丸めた結果はそのまま返るので、**何が起きたかが画面に出る**
- ⚠️ **既定と同じ値は書き残さない**（エンジンの option と同じ。
  書き残すと既定を変えたときに古い値で固まる）
- ⚠️ **駒でないものにこの色を当てないこと。** 一度**手番のマーク（▲/△）**まで
  拾って戻した —— あれは駒ではなく**手番の印**なので、薄くすると
  **今どちらの番かが読めなくなる**
- ⚠️ **候補手の重ね表示（`.study-hint-piece`）は色だけ従い、薄さは別に重ねる。**
  あれが薄いのは「**まだ指していない手**」だからで、駒の字の濃さとは別の意味
  （設定で濃くしても、盤の駒より薄いままでよい）

### 王 / 玉と、馬 / 左馬（2026-08-16）

**同じ駒を別の字で書く。** 中身は**駒フォントの stylistic set**
（`ss01` = 王→玉 / `ss02` = 馬→左馬）で、`core/shogifont` で焼いたフォントには
**どれにも入っている**（同梱でも端末のフォントでも効く）。

| | 先後 | 当て方 |
|---|---|---|
| **玉** | ⚠️ **選べる**（王のまま / 先手だけ / 後手だけ / 両方） | `<shogi-board>` の `gyoku` 属性 |
| **左馬** | ⚠️ **無い**（盤全体） | `hidari-uma` 属性（**有無だけ。値は見られない**） |

⚠️ **玉だけが先後を選べる理由。** 玉は**王将/玉将という駒そのものの呼び分け**
（上位者が王）なので片側だけがありうるが、左馬は**盤の見た目の選択**なので、
使うと決めたら盤全体がそうなる。**左馬に先後の欄を足さないこと。**

⚠️ **`K` と `k` はフォント上で同じグリフ。** だから盤全体にまとめて
`font-feature-settings` を当てると**先後を分けられない**（駒 1 つ 1 つに
当てるしかなく、それをやるのが `<shogi-board>` の `gyoku` 属性）。
その結果、当てる先が 2 通りある:

```
盤（<shogi-board>）        gyoku / hidari-uma 属性       core/web が駒 1 つずつに当てる
ikkyoku が自分で描く駒     --piece-features-black/white  style.css が当てる
```

- ⚠️ **どちらか片方だけ直すと「盤は玉なのに掴むと王」になる。** しかも
  掴まないと分からない。**当てるのは `applyPieceStyle` の 1 か所**にしてある
- **自前で描いていて実際に効くのは 2 つだけ**:
  **「足りない駒」の王**（駒台には王も馬も出てこない —— 王は取られないし、
  成駒は取ると元の駒に戻る）と、**掴んだ駒の絵**（盤から掴むので王も馬も出る）。
  ⚠️ **それでも `.stock-chip` にも当てておくこと** —— 駒を描くところで規則を
  分けると、増やしたときに拾い忘れる
- ⚠️ **「足りない駒」は先手の値を使う**（持ち主が未決なので）。**盤へ落とすと
  先手の駒として置かれる**という既にある規約に合わせてある。
  **後手の値を当て直さないこと**（先後の既定が 2 通りになる）
- ⚠️ **組み立ては Go 側**（`pieceStyle`）。`font-feature-settings` は
  **個別の値が積み上がらない**（後から当てた宣言が丸ごと勝つ）ので、
  **玉と左馬を 1 つの値にまとめてから**渡す。**フロントで組み立て直さないこと**
- ⚠️ **当てるものが無いときは `"normal"`**（空文字は CSS の値として不正で、
  宣言ごと捨てられる）
- ⚠️ **設定の値は `gyoku` 属性の語彙そのまま**（`""` / `"black"` / `"white"` /
  `"both"`）。**別の語彙にしない** —— 変換表を挟むと片方だけ直したときに黙って食い違う
- ⚠️ **「両方」は属性の値を空にして渡す**（＝値なし）。`"both"` でも今は同じに
  描かれる（知らない値は両方）が、**両方を指す決まった書き方は「値なし」のほう**
- ⚠️ **知らない値は「王のまま」に倒す**（`NormalizeGyoku`）。`<shogi-board>` の
  属性は「知らない値なら両方」だが、**あちらは属性が付いている時点で
  「玉を使う」と言っている**。こちらは**使うかどうかも含めて表す欄**なので、
  設定ファイルの打ち間違いで盤の字が勝手に変わってはいけない
- ⚠️ **属性そのものを外すこと**（値を空にして残さない）。残すと
  「値なし」＝**先後とも玉**になる
- **既定は「どちらも王」**（今までの見え方を変えない）
- ⚠️ **ブラウザの HTML/SVG でしか効かない**（Canvas 2D と Go の `x/image/font` は
  GSUB を解釈しない）。**そこで玉・左馬が要るようになったら**、フォントには字も
  同梱してあるので `玉`(U+7389) / **U+E000**（左馬。私用領域）を直接描く
  （`core/CLAUDE.md` の「異体字と反転字」）。⚠️ **U+E000 はこのフォントが勝手に
  決めた位置**なので、駒フォントを当てた要素の中でしか使えない

## テスト（`go test ./...`）

⚠️ **ここに書いてあるのは「何の歯止めか」。消すときはその歯止めが要らなくなったのかを先に確かめること。**

- `piecefont/piecefont_test.go` — **駒の字**（設定タブ）。環境に依存しないのは
  **一覧に出す名前**（⚠️ **日本語名を優先すること** —— 英語名だけだと
  「玉ねぎ楷書激無料版v7改」が `Tamanegi Kaisho Geki FreeVer 7` になり、
  自分が入れたフォントだと分からない。`Regular` / `標準` は足さない）と、
  ⚠️ **並び順に「焼けるもの」を前へ詰めないこと**（探すときは名前で探すので、
  使える/使えないで分かれていると**同じ名前のフォントが離れて並ぶ**）、
  要る字を **`core/shogifont` から取っていること**（ikkyoku 側で数え直さない歯止め）、
  フォントでないファイルを名指しで読んだら断ること。
  ⚠️ **端末のフォントを実際に焼くところは、駒の字を持つフォントが無ければ skip する**
  （あるかどうかでテストが「失敗」に変わると、ツールの問題か環境の問題か
  切り分けられない。`usi/client` が実機エンジンを要求しないのと同じ理由）
