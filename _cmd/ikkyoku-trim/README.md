# ikkyoku-trim

**録画した動画を「盤が変わった前後だけ」に詰めるコマンド**（2026-10-11）。

将棋の対局を録画ソフト（OBS など）で録った動画は何時間にもなるが、盤が動くのは指した前後の数秒だけ。
そこだけを残してつなぎ、短い 1 本の動画にする（200 手 × 前後 10 秒なら 2,000 秒ほど）。
**残すのは対局の盤面の流れ**で、大盤の解説の動きなど、対局の盤でない盤の動きは残さない（下の「対局の盤」）。
作った動画は、画面で再生して確かめたいときに使う。**動画を詰めるだけの道具で、ikkyoku アプリとは関わらない。**

制約（崩してはいけないこと）は `AGENTS.md`。

## 要るもの

- **ffmpeg と ffprobe**（PATH に通しておくか、`-ffmpeg` / `-ffprobe` で場所を渡す）。2026-10-11 に 8.1.1 で確かめた
- Go（このリポジトリのルートから `go run` する）

## 使い方

リポジトリのルートで:

```bash
GOWORK=off go run ./_cmd/ikkyoku-trim "<録画のディレクトリ>"
```

```bash
GOWORK=off go run ./_cmd/ikkyoku-trim "<1 本目の動画>" "<2 本目の動画>"
```

- **ディレクトリを渡すと**、中の動画ファイル（`.mp4` `.mkv` `.mov` `.flv` `.ts` `.webm` `.avi` `.m4v`）を
  **名前の順**に読む。OBS のファイル名は録り始めの日時なので、名前の順が録った順になる。サブディレクトリは見ない
- **ファイルを並べると**、渡した順に読む
- 並べた動画は **1 本の続いた録画として扱う**（録画ソフトは 1 時間を超えると分けて録ることがあるため）。
  分けて録ったあいだに抜けがあって盤が変わっていれば、それも変化として前後を残す
- **録る長さに上限は無い**。動画を丸ごと展開しないので、メモリは長さに関係なく一定（かかる時間は長さに比例する）

書き出すもの（既定）:

| 渡したもの | 動画 | 区間の JSON |
|---|---|---|
| ディレクトリ `rec/` | `rec/rec-trim.mp4` | `rec/rec-trim.json` |
| ファイル `a.mp4` から | `a-trim.mp4`（`a.mp4` の隣） | `a-trim.json` |

あわせて、**対局の盤に決めたコマを切り出した画像** `<名前>-trim-board.png` を書く（大盤を選んでいないかを目で確かめる。
`-region` を渡したときは書かない）。
`-o` で動画の場所を変えると、JSON と画像も同じ名前になる。既にある動画は `-force` が無ければ上書きしない。
名前の終わりが `-trim` の動画は、ディレクトリを読むときに拾わない（同じディレクトリでやり直しても、前の出力が入力に混ざらない）。

### よく使う形

```bash
GOWORK=off go run ./_cmd/ikkyoku-trim -dry-run "<録画のディレクトリ>"
```

区間を探して JSON を書くだけ（動画は書き出さない）。どこが残るかを先に確かめるとき。

```bash
GOWORK=off go run ./_cmd/ikkyoku-trim -segments "<録画のディレクトリ>/<名前>-trim.json" -force
```

JSON の `segments` を手で直したあと、**探し直さずに切り直す**（2 段目だけ）。書き出す先は JSON と同じ名前の `.mp4`。

```bash
GOWORK=off go run ./_cmd/ikkyoku-trim -region 480,270,920,990 "<録画のディレクトリ>"
```

**対局の盤**の位置を**動画の画素**で `x,y,幅,高さ` と渡す。録画の頭が大盤のとき・盤を自動で探せないときに使う。

### フラグ

| フラグ | 既定 | 意味 |
|---|---|---|
| `-o` | 上の表 | 書き出す動画（JSON は同じ名前の `.json`） |
| `-before` | `10s` | 変化の前に残す長さ |
| `-after` | `10s` | 変化の後に残す長さ |
| `-fps` | `4` | 変化を探すときに 1 秒あたり何コマ見るか |
| `-threshold` | `0.0005` | 対局の盤の矩形の中で、明るさが変わった点の割合がこれ以上なら変化 |
| `-scene` | `0.3` | 画面全体か対局の盤の中で、明るさが変わった点の割合がこれ以上なら、対局の盤がまだ映っているかを確かめる |
| `-switch` | `2s` | 対局の盤が映らなくなった・戻ったときに残す長さ（戻ったあとは `-after`） |
| `-region` | （最初に見つけた盤） | 対局の盤の矩形を `x,y,幅,高さ`（動画の画素）で指定する |
| `-segments` | | 変化を探さず、この JSON の区間で切ってつなぐ |
| `-dry-run` | | JSON を書くだけ |
| `-force` | | 書き出す先が既にあっても上書きする |
| `-crf` | `12` | 書き出す動画の画質（libx264 の CRF。小さいほど元に近い） |
| `-ffmpeg` / `-ffprobe` | `ffmpeg` / `ffprobe` | コマンドの場所 |

## 仕組み

**2 段で動く。どちらも ffmpeg が流しながら処理し、動画を丸ごと展開しない。**

### 1 段目: 変化を探す（`scan.go`）

1. ffprobe で各動画の大きさ・長さ・1 秒あたりのコマ数・最初の時刻を調べ、つないだ録画の中での始まり（`offset`）を振る
2. ffmpeg に動画をデコードさせ、**1 秒 `-fps` コマ**の生の画素（RGBA）をパイプで受け取る。持つのは「1 つ前のコマ」と
   「今のコマ」の 2 つだけ（1080p で 1 コマ 8MB ほど）
3. **対局の盤を決める**（下の「対局の盤」）。決めるまでは何も残さない
4. 対局の盤が**映っているあいだ**、1 つ前のコマと今のコマを `ikkyoku.FrameDiff`（明るさが 10 以上変わった点の割合。
   160×160 点で見る）で比べる:
   - **対局の盤の矩形の中**が `-threshold` 以上 → 変化（`why: 盤`。前後は `-before` / `-after`）
   - **画面全体か対局の盤の中**が `-scene` 以上（比べられないときも）→ 対局の盤がまだ映っているかを確かめる。
     映っていなければ「映らなくなった」（`why: 対局の盤が映らなくなった`。前後は `-switch`）
5. 対局の盤が**映っていないあいだ**は何も比べず、2 秒ごとに盤を探す。対局の盤が戻ったら「戻った」
   （`why: 対局の盤が戻った`。前は `-switch` ＋ 探す間隔 2 秒、後は `-after`。映っていないあいだに指された手で盤が
   変わっているので、戻ったあとをしっかり残す）
6. 1 つ前のコマとの比べは**動画の境目をまたいで続ける**
7. 変化ごとに `[時刻 − 前 − 1 コマ, 時刻 + 後]` を残す区間にし、始まりの順に並べて、重なる・接する区間はまとめ、
   つないだ録画の外は切り捨て、動画の境目で分ける（`plan.go` の `buildSegments`）。結果を JSON に書く

### 対局の盤

- **対局の盤は `-region`、無ければ録画の中で最初に見つけた盤**（`recognize.DetectRegion`。suteme の盤の検出。見つかるまでは
  2 秒ごとに探す）。⚠️ **録画の頭が大盤だと、大盤を対局の盤にしてしまう**。`<名前>-trim-board.png` で確かめ、違っていれば
  `-region` で渡す（または対局の盤が映ってから録り始める）
- **それ以外の盤（大盤など）は測らない**。大盤が映っているあいだの解説の駒の動きは残さない。残すのは、対局の盤が
  映らなくなった瞬間と戻った瞬間だけ
- 「対局の盤が映っているか」の見分け方:
  - 盤が見つかれば、対局の盤と**同じ大きさ・位置か**（ikkyoku の追従が「別の盤」を見分けるのと同じ `recognize.Signature.Matches`。
    大きさは 18%、位置はマス 0.8 個ぶんまで同じと見なす。地色は見ない）
  - 盤が見つからなければ、**最後に対局の盤が映っていたときの盤の部分と見比べ**、`-scene` 未満の違いなら映っている
    （盤の検出が苦手な画面で、一度「映っていない」になったら二度と戻らない、を防ぐ。持つのは盤の部分の写し 1 枚だけ）
- **画面の大きさが違う動画に変わったら、対局の盤の矩形を大きさの比で写す**（探し直すと大盤を拾いうるので探さない）
- ⚠️ 中継の画面配置が途中で変わって**対局の盤の大きさ・位置そのものが変わると、別の盤と見なして以後を残さない**。
  そういう録画は、配置が変わるところで分けて、それぞれに `-region` を渡す

**つなぎ目で盤は飛ばない**: 変化の前後をすべて残すので、残した区間と区間のあいだでは盤は変わっていない
（飛ぶのは持ち時間の表示や画面の隅くらい）。

### 2 段目: 切ってつなぐ（`cut.go`）

- 動画ごとに ffmpeg の `select='between(t,始め,終わり)+…'` で残す区間のコマだけを通し、`setpts` で時刻を詰めて振り直す。
  区間の時刻には動画の**最初の時刻**（`startTime`）を足す（mpeg-ts などは 0 から始まらない）
- 複数の動画は `concat` で 1 本につなぐ。**画面の大きさが違う動画が混ざったら最初の動画の大きさに合わせる**（画素が変わるので
  ターミナルに ⚠ を出す）
- フィルタは区間が何百もあると長くなるので、**ファイルに書いて `-/filter_complex` で渡す**（Windows のコマンドラインの長さの上限）
- 書き出しは libx264（`-crf` 12・`preset medium`・`yuv420p`）。**音は入れない**

## 区間の JSON

| キー | 中身 |
|---|---|
| `inputs` | 読んだ動画（`file`・`width`・`height`・`duration`・`frameRate`・`startTime`・`offset`＝つないだ録画の中の始まりの秒） |
| `before` / `after` / `fps` / `threshold` / `scene` / `switch` | 使った設定 |
| `boards` | 対局の盤を決めた記録（`file`・`time`・`rect`・`confidence`・`how`＝`detect`（最初に見つけた盤）/ `region`（指定）/ `scaled`（画面の大きさが違う動画に変わったので比で写した）） |
| `changes` | 変化と見なしたコマ（`file`・`time`＝その動画の中の秒・`at`＝つないだ録画の中の秒・`board`＝対局の盤の中の割合・`scene`＝画面全体の割合（どちらも測っていなければ -1）・`why`＝`盤` / `対局の盤が映らなくなった` / `対局の盤が戻った`・`before` / `after`＝この変化の前後に残す秒） |
| `quiet` | **変化と見なさなかったコマ**の、対局の盤の中の割合の分布（`edges[i]` 以上 `edges[i+1]` 未満が `counts[i]`。`max`＝最大）。線を詰める材料 |
| `segments` | 残す区間（`file`・`start`・`end`。その動画の中の秒）。**2 段目はこれだけを見る**ので、手で直すならここ |
| `total` / `kept` | つないだ録画の長さ・残す長さ（秒） |

## 線を詰める

`-threshold`（0.0005）と `-scene`（0.3）は**当て推量**（2026-10-11）。本物の録画を詰めるときに見直す。

- **迷ったら敏感な側に倒す**。余分に拾っても動画が数秒長くなるだけだが、見落とした変化は詰めた動画から消えて戻らない
  （駒が少し動いた・手が盤に掛かったような小さな変化こそ残したい）
- `quiet.max` と `quiet.counts` を見る。変化と見なさなかったコマの割合が `-threshold` のすぐ下に固まっていれば、
  配信の圧縮の揺らぎを拾いかけている。`changes` の `board` が線のすぐ上のものばかりなら、揺らぎを変化と見なしている
- `-dry-run` で JSON だけ作り直して比べると速い（2 段目の書き出しを待たない）

## 確かめたこと（2026-10-11）

- **`trim_test.go`**（`GOWORK=off go test ./_cmd/ikkyoku-trim`）: 入力の並べ方・区間の組み立て・ffprobe の答えの読み方・
  ffmpeg のフィルタの組み方と、**ffmpeg で作った 6 秒の動画 2 本を通しで詰める**テスト（3 秒と 8 秒の変化の前後 1 秒ずつが残り、
  約 4.5 秒の 1 本になる。境目では変化と見なさない）。ffmpeg が無ければ通しのテストは飛ばす
- **盤を自動で探せること**: suteme の学習データの盤の画像（1745×1338）を、まわりに余白を付けて 12 秒の動画にし、6 秒で
  盤の中に小さな四角を出したもので試した。盤は最初のコマで信頼度 1.00 で見つかり、6 秒の変化の前後が残った
- **対局の盤だけを残すこと**（`TestScanKeepsOnlyGameBoard`）: 青い四角を対局の盤、赤い四角を大盤と見なす検出に差し替え、
  ffmpeg で作った 12 秒の動画（青 0〜4 秒・赤 4〜8 秒・青 8 秒〜。赤の上で 5 秒と 6 秒に駒が動き、青には赤のあいだに 1 つと
  10 秒に 1 つ駒が来る）で、変化が「4 秒 映らなくなった・8 秒 戻った・10 秒 盤」の 3 つだけになる。盤の検出が無いときに
  最後に映っていた盤の部分と見比べることも別のテスト（`TestGameBoardShowsWithoutDetection`）
- **気づいたこと**: 盤の画像から作った動画では、変化の 2 秒あとに**圧縮が画質を詰め直した揺らぎ**（盤の中の割合 0.00055）が `-threshold`
  をわずかに超えて、もう 1 つの変化になった。区間は 1 つにまとまったので害は無い（残す長さが少し延びるだけ）

## 決まっていないこと

- **本物の録画ではまだ通していない**（上の確かめはどれも作った動画）
- **線**（上の「線を詰める」）。配信の圧縮の揺らぎで毎コマ変化になると、全部が残って詰まらない
- **長く何も起きない場面**。詰めると長考のような「何も起きない長い時間」が消える。ところどころ長い区間を残す指定が要るか
- **対局の盤を最初に見つけた盤で決めてよいか**（録画の頭が大盤なら誤る。今は `-trim-board.png` で目で確かめて `-region` で直す）。
  本物の録画で困るようなら、盤の候補が複数映るときの選び方を考える（suteme の盤の検出は 1 つしか返さない）
- **`-scene` と、映っているかの見分け方**。手が盤を大きく覆った 1 枚で「映らなくなった」になりうる（その瞬間は前後 `-switch`
  ぶん残り、戻ったときに前を長めに残すので、手の動きは概ね残る）。本物の録画で、手で切れていないかを JSON の `changes` で見る
- **詰めた動画の置き場所**。数 GB になりうるので git には入れない。どこに置いて残すか
