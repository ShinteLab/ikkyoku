## 1. 何の話か

ふわりと将棋の棋譜速報は**手で書いた KI2**（移動元が無い）なので、記録の誤記が混じる。誤記には 2 種類ある:

| 誤記 | 例 | 誰が見つけるか |
|---|---|---|
| **盤に当てられない手** | 動かせる駒が無い・絞れない・表記が読めない | **kicho**（保存のたびに本文から計算する「エラーの印」） |
| **盤には当たるが実際と違う手** | 打ち間違いがたまたま指せる手になっている | **人**（kicho にも ikkyoku にも分からない） |
| **反則手** | 二歩・王手放置・打ち歩詰め（KIF / CSA は移動元を信じるので kicho は見ない） | **ikkyoku**（合法手の判定 `legal` を持つのはここだけ） |

kicho は「**持つ・繋ぐ・見せる**」だけで、**判断も訂正もしない**（kicho の `AGENTS.md`「エラー・指摘・派生棋譜」）。
**直す操作そのものと反則手の発見は ikkyoku の役目。**

## 2. kicho が持っているもの（v0.6.0）

| | 中身 | 付けるのは | 取り直すと |
|---|---|---|---|
| **エラーの印** `Record.ErrorMove` / `Error`（`Fetched` にも付く） | 盤に当てられない最初の手（1 始まり。0 = 無し）と理由 | kicho が本文から毎回計算する | 計算し直される |
| **指摘** `store.Flag`（`Library.Flag` / `Unflag` / `Flags`） | 手数（**0 = 棋譜全体**）・理由・誰が（`By`）・付けた時点の本文のダイジェスト | 人・ikkyoku | **残る**。本文が変わると `Flag.Stale` |
| 指摘の集計 `Record.Flags` / `FlaggedMove` / `FlagsStale` | 件数・指摘された最も若い手・古くなったものがあるか | （読むたびに計算） | — |
| **派生棋譜** `Library.SaveDerived(親, store.RelationCorrection, KIF)` | 直した結果。親に繋いだ別の 1 局（`derived`。取り直せない） | ikkyoku | 子は固定。親が変わると `ParentChanged`、消えると `ParentMissing` |
| 親子の集計 `Record.ParentID` / `Relation` / `Children` | | | |
| 「要確認」の絞り込み `store.Query{NeedsAttention: true}` | エラーの印か指摘のある棋譜だけ | | |

- `Library.Flag` は**棚に入っている棋譜にしか付けられない**（棋譜の id が要る。無ければ `store.ErrNotFound`）。
  理由が空なら `ErrNoInput`、手が負なら `ErrInvalidMove`
- ⚠️ **指摘をエラーの印へ寄せて書かないこと**（kicho の約束。あちらは取り直しで消える）
- `By` は ikkyoku が自動で付けたものを **`"ikkyoku"`**、人がメニューから付けたものを **`"user"`** にする

## 3. 前提: ikkyoku が KI2 を読めること（**kicho を v0.5.0 以上に上げるときに要る**）

- v0.5.0 から、ふわりと将棋の `Fetched.KIF` は **KI2 の原本**（`Format: ki2`）。今の `position.FromKifu` は CSA 以外を
  `kifu.Parse`（KIF だけ）に回すので、**上げただけだと 0 手で読み込まれる**。
  `kifu.IsKI2` → `FromKI2` の分岐を足す（仕様は core。`kifu.ParseKI2` と `kifu.KI2Decoder`）
- ⚠️ **原本の指し手を、読めなかった手の先まで持っておくこと。** 今は止まった手から先を捨てているが、
  直したあとに**続きを読み直す**のにそれが要る（「6. 直しの表」）
  - KI2 … `KI2Decoder` に**直した局面**を渡せば、残りの表記をそこから読める（移動元が無いので）
  - KIF / CSA … 残りは移動元つきの手なので、そのまま当て直し、当たらなければそこで止める
- 兄弟を上げるときは kicho v0.6.0 と core v0.5.0 を 2 つの go.mod の両方で（スキル `ikkyoku-build`）

## 4. 呼び名

画像の局面を直す「**訂正タブ**」と混ざるので、ikkyoku の中では次のように呼ぶ。

| 呼び名 | 何か |
|---|---|
| **直す / 直した手** | 手順リストで原本の手を別の手にすること / その手 |
| **原本** | 取得元・棚にある棋譜そのもの（kicho の親） |
| **訂正版** | 直した本譜を棚に入れたもの（kicho の子。関係は `correction`） |
| **指摘** | kicho の `Flag`。「この手が違う」という印。本文は変えない |

⚠️ **「訂正」を手順リストの操作名に使わない**（訂正タブの操作と区別が付かなくなる）。

## 5. 決めたこと

1. **直す場所は解析タブの手順リスト。** 訂正タブは画像の局面の作業場なので使わない
2. **原本は書き換えない。** 直した結果は訂正版（子）として別に残し、指摘は原本に付く印にする
3. **モードを作らない。** 盤でいつもどおり指してから、その手を右クリックして「直しにする」と言う。
   モードは間違えたことに気づけない（`TODO.md` 1 の「UI で決めること」）。
   ⚠️ **自分の枝が黙って本譜になる道を作らない** —— 本譜が変わるのは人が右クリックで言ったときだけ
4. **原本の手は消さない。** 直した手が本譜に入り、原本の手は枝に下がる（取り直しの `Graft` と同じ「消さずに据える」）
5. **直しは表として持ち、木には焼き付けない**（「6. 直しの表」）
6. **訂正版を棚に入れる口は投了の行の右クリック**（今の「棋譜に登録」に相乗りする）。対局中の子は作らない
   （親は取り直すたびに伸びるが、子は固定なので）
7. **反則手は ikkyoku が見つけて指摘にする**（棚の棋譜のとき。「8. 指摘」）
8. **画面で本文を読んで判定しない。** エラーの印・指摘・親子は kicho の値を、直せるかどうかは Go 側の値をそのまま出す

## 6. 直しの表

取り直しの `Graft` は**原本の手を本譜（`kids[0]`）へ据え直す**。木の上で本譜を入れ替えただけだと、
**盤に当たる誤記の直しは次の取り直しで枝へ押し戻される**（盤に当たらない誤記は、原本の手が生えないので残るが、
それに頼ると 2 種類の誤記で振る舞いが変わる）。そこで直しは検討が**表**で持つ:

| 列 | 中身 |
|---|---|
| 手数 | 原本の何手目か（1 始まり） |
| 原本の表記 | その手の原本の表記そのまま（KI2 なら `▲７七同角`。KIF / CSA なら表記と移動元） |
| 種類 | **置き換え**（その手を別の手に）/ **足す**（その手の前に抜けていた手を入れる）/ **飛ばす**（二重に書いた手を除く） |
| 直した手 | USI（置き換え・足すのとき） |

- **原本を読むたびに、表を当ててから `Graft` する。** 読み込み・再読み込み・自動更新の 3 つとも**同じ 1 本**を通す
  （分けると片方だけ直しが消える）
- 当て方は、原本の手の並びを先頭から辿り、表にある手数で置き換え・足す・飛ばすをしてから、**直した局面から残りを読み直す**
  （KI2 は `KI2Decoder`、KIF / CSA は移動元つきの手）。読み直した先で当たらなければ、そこで止める（次の ⚠ の行）
- **当てる前に原本の表記を比べる。** 表に書いた表記と同じ手数の原本の表記が
  - **同じ** → 当てる
  - **違う・その手が読めるようになった**（サイトが直した）→ **その直しを外し、1 回だけ知らせる**
    （例:「47 手目は原本が直りました」。再読み込みの `KifuLoad.Note` と同じ口）。⚠️ **黙って外さない**
- ⚠️ **手数がずれる直し（足す・飛ばす）より後ろの直しの手数は、原本の手数で持つ**（直したあとの手数で持つと、
  前の直しを取り消したときに後ろの直しが別の手を指す）
- 表は**控え（`StudyRecord`）に書く**。鍵は今の控えと同じ（`sourceKey` / `gameID`）。次に同じ棋譜を開いたら直しが戻る
- ⚠️ **根を入れ替えたら表を捨てる**（`sourceURL` / `gameID` と同じ。残っていると別の棋譜に当たる）
- ⚠️ **直した手を推測の手（橙）と同じ扱いにしない。** 推測は後の 1 枚で差し替えてよいが、直しは人が言った手
- 設計原則1（履歴に依存しない）は崩れない: 表は「この原本をこう読む」という人の指示で、無くても原本どおりに読めるだけ

## 7. 画面

### 7.1 止まった所を手順リストに出す

今は止まった理由がステータスの 1 行（`KifuLoad.Note`）に出るだけで、どこか分からない。手順リストに行として出す:

```
 45 ▲７九玉
 46 △４四銀
 47 ⚠ ▲７七同角        ← 押せない行（投了の行と同じ扱い）。ホバーで理由。右クリックでメニュー
 48   △６五歩          ← 読めていない原本の残り。灰色・原本の表記のまま・押せない
 49   ▲同　歩
 …   （残り 21 手）
```

- ⚠ の行と灰色の行は**節点にしない**（終局の行と同じ。指し手ではないので、節点にすると解析・分岐・中継の繋ぎ先がずれる）。
  Go 側が `StudyState` に「止まった手数・原本の表記・理由・残りの表記」として載せ、フロントは描くだけ
- 残りを見せるのは「**直せば続きが読める**」と分かるようにするため。長ければ数手だけ出して残りは手数で畳む
- ⚠ は **kicho のエラーの印と、ikkyoku が盤に当てて止まった所の両方**に出る（KIF / CSA の反則手は kicho が見ないので、
  ikkyoku で止まって初めて分かる）。理由の文は止めた側のもの

### 7.2 手の印

手の後ろの印は今の「人が指した黒丸」「エンジンの色の丸」「推測の橙」と並ぶ。⚠️ **重ねてよい**（どれも本当）。

| 印 | どこに | ホバー |
|---|---|---|
| ✎ | 直した手（本譜に入った手） | 「原本: ▲７七同角」（足した手は「原本に無い手」） |
| 取り消し線 | 枝に下がった原本の手 | 「原本の手（47 手目で直しました）」 |
| ⚑ | 指摘のある手（棚の棋譜だけ） | 指摘の理由と誰が付けたか。`Stale` なら薄くして「指摘のあとに原本が変わりました」 |

- 棋譜全体への指摘（手数 0）は手順リストに出さず、棋譜タブの詳細に出す（「7.4」）

### 7.3 右クリックのメニュー

| 右クリックしたもの | 出す項目 | 何が起きるか |
|---|---|---|
| ⚠ の行の 1 つ前の局面で指した手 | **47 手目の直しにする（残り 21 手を読み直す）** | 表に「置き換え」を足す。原本の 48 手目から先を読み直す |
| 同上 | **抜けていた手として足す（原本の ▲７七同角 を 48 手目に回す）** | 表に「足す」を足す。原本の 47 手目から先を読み直す |
| ⚠ の行 | **この手を飛ばす** | 表に「飛ばす」を足す。原本の 48 手目から読み直す |
| 本譜の N 手目と分かれる枝の手（盤に当たる誤記） | **本譜の N 手目の直しにする** | 表に「置き換え」を足す。枝の手が本譜に、原本の N 手目は枝（取り消し線）に。N+1 手目から先を読み直す |
| ✎ の手 | **直しを取り消す** | 表から外して原本どおりに据え直す。直した手は人が指した枝として残る（消さない） |
| 本譜の手（棚の棋譜） | **指摘する…** | 理由を 1 行書いて ⚑ を付ける（`Library.Flag(id, 手数, 理由, "user")`）。正しい手が分からないとき用 |
| ⚑ の手 | **指摘を外す** | `Library.Unflag`。⚠️ **ikkyoku が付けた反則手の指摘も外せる**（実際に指された反則手ということもある） |
| 投了の行（直した手があるとき） | **訂正版として登録**（今の「棋譜に登録」の代わり） | 「7.5」 |

- ⚠️ **項目を出す条件は Go 側で決める**（今の `canRegister` / `canUnresign` と同じ形）。フロントで手数を比べない
- ⚠️ **「直しにする」は原本を持つ検討だけ**（棋譜・URL・棚から読んだもの）。撮った局面や新規対局には原本が無いので出さない
- 直したあと読み直した続きで**また当たらなければ、そこに次の ⚠ の行が出る**。直しは 1 か所ずつ積む
- ⚠️ **読み直した続きが原本の最後まで載り、原本に終局があれば終局の行を出す**（投了の行が出ないと訂正版を登録できない）
- メニューの約束は今の手順リストと同じ（2 段階・`danger` にしない・右クリックした行を先に選ぶ。`_docs/ui/moves.md`）

### 7.4 棋譜タブ・入力タブのカード

- kicho の値をそのまま出す（⚠️ **画面で本文を読んで判定しない**）。並びは kicho アプリ（`ErrorBadge` / `LineageTags`）に揃える:
  `⚠ N手目`（理由はバルーン）・`指摘 N`（古いものがあれば薄く）・`訂正版`・`親が更新`・`親は削除済み`・`派生 N`
- カード（取得しただけ）に出るのは `⚠ N手目` だけ（指摘と親子は棚の行の持ち物）
- 棋譜タブの詳細に**指摘の一覧**（手数・理由・誰が・古いか）と**子（訂正版）の一覧**を出す。子にはそれぞれ「解析する」。
  棋譜全体への指摘（手数 0）を付けるのもここ（「この棋譜に指摘する…」）
- 棋譜タブの絞り込みに「**要確認**」（`Query.NeedsAttention`）を足す
- **`親が更新` の子を直し直すときは親を開く。** 直しの表は親の控えにあるので当て直され、もう一度「訂正版として登録」すると
  新しい子が増える（kicho は子を何個でも持てる。どれを使うかは決めない）。子は普通の KIF なので直しの表は持たない

### 7.5 訂正版として登録（投了の行）

- 親は**原本**。棚に無ければ（入力タブのカードから解析しただけ）先に原本を親として保存し、カードは今の「棋譜に保存」と同じく閉じる
- 子は**直した本譜の KIF**（`SaveDerived(親, correction, …)`。対局名などは kicho が親で埋める）
- **盤に当たる誤記を置き換えた手には、親に指摘も付ける**（`Flag(親, N, "実際は △…", "ikkyoku")`）。
  盤に当たらない誤記は kicho のエラーの印が既にあるので付けない
- 今の `registerableLocked` は「棚と結んでいる」「URL から読んだ」を断っているが、**直した手があるときは通す**（親子で入るので）
- 登録したら検討は**子と結ぶ**（`gameID` を子の id に）。⚠️ 直しの表は親の控えに残す（直し直すのは親から）

## 8. 指摘

### 8.1 人が付ける

「7.3」のメニュー（手）と「7.4」の棋譜タブ（棋譜全体）。`By` は `"user"`。

### 8.2 ikkyoku が反則手を見つけて付ける

kicho は KIF / CSA の移動元を信じるので、**二歩・王手放置・打ち歩詰め・動けない駒**などは kicho のエラーの印に出ない。
ikkyoku は棋譜を 1 手ずつ合法手として指す（`Study.Play` → `checkLegal`）ので、**止まった所が反則手**になる。

- **棚の棋譜を読んで反則手で止まったら、その手に指摘を付ける**（`Flag(id, 手数, 理由, "ikkyoku")`。理由は止めた側の文）
- ⚠️ **同じ指摘を重ねない。** 同じ手数に `By == "ikkyoku"` で古くない（`!Stale`）指摘があれば付けない
  （開くたび・取り直すたびに増える）
- ⚠️ **人が外した指摘を付け直さない。** 外したことを控えに覚えておき、本文が変わるまでは付けない
  （実際に指された反則手で反則負けになった対局は、記録として正しい）
- ⚠️ **kicho のエラーの印がある手には付けない**（盤に当てられない手は既に印がある。二重に出さない）
- 棚に無い棋譜（カード・貼り付け・URL）には付けない（付け先が無い）。⚠ の行は出る
- ⚠️ **付けられなくても読み込みは止めない**（棚が開けない・書けないとき。設計原則3）

## 9. 決まっていないこと

- **指摘を棚に無い棋譜にも付けられるようにするか。** 今の案は「棚の棋譜だけ」（指摘は kicho の棋譜の行に付く印なので）。
  付けるなら控えに持っておき、棚に入れたときに渡す
- **反則手の指摘を開いたときに自動で付けるか、⚠ の行のメニュー（「指摘として残す」）で付けるか。** 今の案は自動
  （kicho の `TODO.md` もその前提）。棚に黙って書くのが嫌なら手動に倒す
- 灰色の残りを何手まで出すか（実機で見て決める）
