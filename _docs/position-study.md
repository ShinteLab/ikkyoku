# position: 手の木（先端・終局・控え・分かれ道・legal との層）

**`study.go` / `snapshot.go` / `move.go` を触るときに読む。** `position/AGENTS.md` から分けた**制約**（「⚠️ …しないこと」）で、
⚠️ **自動では読まれないので、触る前に必ずここを開くこと**（索引は `position/AGENTS.md`）。

## 本譜の先端（`Study.MainTip`）

**中継を追うときの繋ぎ先。** ⚠️ **`Current()` ではない** —— ユーザーが枝の途中を
読んでいるのは普通で、そこを繋ぎ先にすると**検討の枝に中継の手が生える**。
⚠️ **`MainLine` と同じところで止まる**（「分岐にする」で下げた手から先は本譜ではない）。
⚠️ **見ている場所は動かさない**（読むだけ）。

## 対局の終わり（`Study.RecordEnd` / `SetRecordEnd`）— **2026-09-16**

**棋譜に終局（投了・中断など）が書いてあった節点。** ここから先に伸びている手は
**対局の手ではなく検討**で、中継で言う**「投了図以下」**がそれ。

- ⚠️ **推測で立てないこと。** 「詰んでいるから終わり」も「これ以上手が無いから
  終わり」も**棋譜の事実ではない**。立ててよいのは**棋譜に終局印があった**ときだけ
  （`kifu.Document.EndMark`）。⚠️ **最後まで読めたときだけ**（途中で止まったなら
  そこは対局の終わりではない）
- ⚠️ **`variation` とは別の事実。** あちらは**人が「これは検討だ」と言った**印、
  こちらは**棋譜にそう書いてあった**という事実。**片方で代用しないこと** ——
  投了図から並べただけの手には `variation` が付かない
- ⚠️ **知らない節点なら忘れること**（0 に戻す）。据え直しで節点が入れ替わったのに
  前の id を持ち続けると、**関係の無い手に「対局の終わり」の印が出る**
- ⚠️ **控えに入れること**（`StudySnapshot.End`）。落とすと開き直したときに
  **投了図以下の印が消える**（棋譜から読み直す口が無いので二度と戻らない）
- ⚠️ **`MainLine` / `MainTip` / `Line` の 3 つが必ずここで止まること**
  （2026-09-16 に実機で指摘されて直した）。止めないと**投了図以下が本譜として
  扱われ**、⚠️ **棚へ書き出す KIF に検討の手が対局の手として載る**
  （「嘘の棋譜が棚に入る」）うえ、**中継の繋ぎ先が対局の終わりより先を指す**
- ⚠️ **止まる条件は 2 つで、`Line` だけ違う。** `MainLine` / `MainTip` は
  `mainNext`（`variation` ＋ `end`）、**`Line` は `end` だけ** ——
  **候補手の列（`AddLine`）は `variation` が付いていても経路として伸びる**
  （続きが他に無いのだからそれが今の経路で、連続解析もそこを辿る）。
  **片方の条件をもう片方に流用しないこと**
- ⚠️ **本譜のロックそのものではない**（`TODO.md` 1 は未決のまま）。持っているのは
  「どこで対局が終わったか」だけで、**手を消す/消さないの判断には使っていない**

## 検討の控えと復元（`Study.Snapshot` / `RestoreStudy`）

**再起動しても前回の続きから始められるように、木を丸ごと出し入れする**
（2026-09-16。`snapshot.go`）。

- ⚠️ **節点の id をそのまま持つこと。** 評価値の鍵が id（`app.EvalPoint.ID`）なので、
  **復元で振り直すと点が全部迷子になる。** `Play` で積み直す形の復元は**できない**
- ⚠️ **`Nodes` の並びが木の形そのもの**（親が先の前順・兄弟は順番どおり）。
  **並べ替えて保存すると本譜と変化が入れ替わる**（`kids[0]` が本譜側）
- ⚠️ **印を落とさないこと**（`Hand` / `Guess` / `Sources` / `Variation` / `Chosen`）。
  あれが**「実際に現れた指し手か、仮定か」**を持っている。とくに **`Guess`
  （追従が推測で足した印）を落とすと、嘘が実際の指し手として残る** ——
  `TODO.md`「本譜のロック」が一番避けたい壊れ方そのもの
- ⚠️ **`HandsFixed` と `MateProblem` は SFEN では往復しない**ので別に持つ。
  `FromFullSFEN` は必ず `HandsFixed` を立てるので、**撮って確定した局面が根だと
  食い違う**（駒台の逆算が復活する）
- ⚠️ **`NextID` を控えること。** 最大の id + 1 で済ませると**消した id を使い回す**
  ことになり、走っていた解析が**別の節点の評価値として書き戻る**
- ⚠️ **復元で合法性を見直さない**（控えは自分が書いたもの）。全節点で
  `legal.Moves` を回すと節点の数だけ探索が走る。代わりに**見ていた節点の局面だけ
  組み立て直し**、そこで落ちたら復元しない
- ⚠️ **見ていた節点が見つからなければ根に戻す**（復元そのものは続ける）。
  **居場所が分からないだけで検討を全部捨てる理由が無い**（設計原則3）
- ⚠️ **これは棋譜ではない。** 配る形（KIF の `変化：N手`）は `core/kifu` が決める。
  **交換形式にしないこと**

## 経路の分かれ道（`Study.Branching`）

**評価値グラフの欄外に「ここに別の手順がある」という印を打つ**のに使う
（2026-09-16）。**今の経路の上で、子が 2 つ以上ある節点**の id を返す。

- ⚠️ **本数を返さないこと。** 印は「在るか無いか」だけ —— 帯は 10px しかなく、
  本数を積むと 2 本で天井になる（`_docs/ui/evalgraph.md`）
- ⚠️ **今の経路の上だけ**（`Line` と同じ 1 本）。グラフが描くのはその 1 本なので、
  そこに乗っていない分かれ道は**指す場所が横軸に無い**
- ⚠️ **子の数だけで判断しないこと**（2026-09-16 に実機で足りなかった）。
  印を打つのは**「ここから先は 1 本道の本譜ではない」**の 3 通り（`branches`）:
  **子が 2 つ以上** / **続きが `variation`**（「分岐にする」）/
  **そこで対局が終わっている**のに続きがある（`end`。**投了図以下**）。
  ⚠️ **後ろ 2 つは子が 1 つしかない** —— 落とすと、**本譜の投了位置から詰みまで
  並べたときに印が出ない**（中継を観ながら一番やること）
- ⚠️ **`Fork` とは別物。** あちらは**今居る枝がどこから分かれたか**の 1 か所を返す
  （比べる相手の経路つき）。こちらは**経路上の分かれ道ぜんぶ**

## Go 側の層（`position.Study` / `ikkyoku/legal`）

```
StudyService ──> position.Study ──> position.Position.ApplyMove   手を盤に反映する
                       └────────> ikkyoku/legal.Moves ──> engine  合法かどうかを言う
```

- **`position.Study` は「根 + 指した手の並び」を持つ。** 今の局面は毎回組み立て直す。
  ⚠️ **局面を単体で持たないこと** —— 手順とずれたときにどちらが本当か分からなくなる。
  この形にしてあるのは、**エンジンに渡すのがまさにこの形**（`position sfen <根> moves ...`）
  なのと、**戻る操作が並びを短くするだけで済む**（逆再生を書かなくてよい）から
- ⚠️ **これは設計原則1（履歴に依存しない）に反しない。** 根の 1 局面だけで解析は
  成立していて（手順が空でよい）、手順は**ユーザーが自分で伸ばしたもの**。
  中継を最初から観ていなくても、撮った 1 局面から手を進められる
- **合法性の判定は `ikkyoku/legal` だけ。** `position.ApplyMove` は「決まった手を
  盤に反映する」だけで合法性を見ない（**分けてあるので `position` が engine を
  知らずに済む**）。⚠️ **合法手生成が要るので `ikkyoku → engine` の Go 依存が戻った**が、
  **用途が違う**（手の検証であって解析ではない）。
  **解析をこちら経由に戻さないこと** —— 棋力の問題を設定の問題にした意味が無くなる
- ⚠️ **`legal.Moves` は panic を握る。** 訂正 UI は不正な局面も確定できるので、
  想定外の局面が来る。**アプリごと道連れにしないこと**（設計原則3）
- ⚠️ **合法手が出せなくても局面は返す**（`StudyState.LegalError`。エラーにしない）。
  手が指せなくなるだけで、盤も解析もそのまま使える。**理由は画面に出すこと** ——
  出さないと「駒を押しても光らない」の理由が分からない
- ⚠️ **手を足す口は 3 つ。「進むか」と「出所を残すか」で使い分ける**
  （`Play` / `AddLine` / `PlayLine`。2026-09-14 に 3 つめが入った）。

  | | 進むか | 印 | 誰が呼ぶか |
  |---|---|---|---|
  | `Play` | **進む** | `Hand`（人が指した） | 盤のクリック・`FromKIF` |
  | `AddLine` | **進まない** | `Sources`（エンジン） | 候補手の右クリック →「手順を追加」 |
  | `PlayLine` | **進む** | `Sources`（エンジン） | 候補手の右クリック →「手順を指す」 |

  ⚠️ **`PlayLine` の `head` は指し継ぐ列の 1 手目だけ真にすること。** 毎手立てると
  `Nodes` の字下げが 1 手ごとに 1 段増え、**40 手指させたら 40 段の階段**になる。
  ⚠️ **既にある手には立たない**（本譜の続きをなぞっただけで**実際に現れた指し手が
  変化に落ちる** —— `Branch` を黙って押すのと同じ）。
  ⚠️ **1 手目を頭にしてあるのは本譜を 1 手も動かさないため** —— エンジンが指した手は
  実際に現れた指し手ではないので、`AddLine` と同じ扱いにする
- ⚠️ **座標の読み替えは `legal` と `position/move.go` の 2 か所だけ。**
  `core/usi` の内部 x は**筋番号ではない**（`FormatSquare` が `10-x` を書くので
  7 筋は x=3）。x=1 が 9 筋で、`core/sfen` の file の数え方と一致する。
  **間違えると、見た目は動くのに 1 マスずれた手を指す**（テストで固定してある）
