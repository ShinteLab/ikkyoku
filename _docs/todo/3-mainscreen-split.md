共有していた。どの変更がどのタブに効くかを型で追えない。フロントにはテストが無い（歯止めは `tsc` と `check-css.mjs` だけ）。

## 崩さないこと

`_cmd/ikkyoku/frontend/src/AGENTS.md` の「絶対に崩さないこと」15 箇条。割るときに特に効くもの:

- ⚠️ **局面の写しをフロントに持たない**（5）。割った先に状態のコピーを作らない（ハンドルで読む）
- ⚠️ **同じ値を 2 か所に描くときは更新経路を 1 本にする**（9）。割ったせいで描く口が 2 つにならないこと
- ⚠️ **盤の大きさは式で決まる**（1）・**グリッドはタブを開いた瞬間に測り直す**（2）。`selectTab` の中の測り直しは
  呼ぶ順番を変えない
- ⚠️ **組む場所（`mountXxx` を呼ぶ位置）を動かすときは、イベントを聞く順番と起動時の呼び出しの順番が変わらないか見る**
  （どれも今までの位置で組んである。例外は入力タブで、`#status` を撮る経路が使うので innerHTML の直後）
- ⚠️ **画面に操作方法や説明の文を足さない**（ユーザーの共通の指示）
- `style.css` は割らない。id や class を変えない
- 新しいファイルで `root.innerHTML` に markup を書くなら `check-css.mjs` の `files` に足す（バッククォートの検査）
