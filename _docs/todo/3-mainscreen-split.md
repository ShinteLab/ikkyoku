# `mainscreen.ts` をタブごとに割る

2026-11-13 の全体の見直しで出た改善点。**まだ実装していない。** 終わったらこの文書を消し、
`_cmd/ikkyoku/frontend/src/AGENTS.md` のファイル表を直し、`TODO.md` 7 の行を消す。

## 何が問題か

`_cmd/ikkyoku/frontend/src/mainscreen.ts` は 6,425 行で、中身は **`mountMainScreen` という関数 1 つ**（308 行目から末尾まで）。

- クロージャの中にローカルの `let` / `const` が 324 個、`Events.On` が 20 個
- 5 つのタブ（入力・棋譜・訂正・解析・設定）が同じクロージャの変数を共有している
- フロントにはテストが無い。歯止めは `tsc` と `check-css.mjs` だけ

どの変更がどのタブに効くかを型で追えない。`sidepane.ts`（2,688 行）も同じ形（`mountSidePane` 1 つ）だが、
あちらは 2026-09-08 に `mainscreen.ts` から切り出した結果で、**受け渡しを `opts` と戻り値のハンドルに絞る**という型が
できている。同じ型で続ける。

## 進め方（1 タブ 1 コミット。振る舞いを変えない）

1. **設定タブから。** 新しいファイル（仮に `settingstab.ts`）に `mountSettingsTab(root, opts): Handle` を作り、
   上の範囲を移す
2. **共有している変数を数える。** 移した直後に `npx tsc --noEmit` を流すと、クロージャの外に置き去りになった名前が
   全部エラーで出る。それが `opts`（もらうもの）と `Handle`（返すもの）の一覧になる。
   **20 を超えるなら範囲の切り方が悪い**ので、範囲を狭めてやり直す（例: エンジンの一覧だけ → 駒の字だけ）
3. **`Events.On` は移した側で登録する**（そのタブしか使わないイベントなら）。両方が聞くイベントは `mainscreen.ts` に残して
   ハンドルを呼ぶ
4. 次は入力タブ（新規対局・手合割・URL・画像ファイル。3895〜4740 行あたり）、その次に訂正データの送信
5. **解析タブの盤と寸法（2084〜3860 行）は最後。** 盤の大きさの式・スプリットバー・切り離しが絡み合っていて、
   `_docs/ui/layout.md`（697 行）を読んでからでないと切れない

## 崩さないこと

`_cmd/ikkyoku/frontend/src/AGENTS.md` の「絶対に崩さないこと」15 箇条。割るときに特に効くもの:

- ⚠️ **局面の写しをフロントに持たない**（5）。割った先に状態のコピーを作らない
- ⚠️ **同じ値を 2 か所に描くときは更新経路を 1 本にする**（9）。割ったせいで描く口が 2 つにならないこと
- ⚠️ **盤の大きさは式で決まる**（1）・**グリッドはタブを開いた瞬間に測り直す**（2）。`selectTab` の中の測り直しを
  割った先へ持っていくときは、呼ぶ順番を変えない
- ⚠️ **既定値の解決をフロントに書かない**（7）・**色を直書きしない**（15）
- ⚠️ **画面に操作方法や説明の文を足さない**（ユーザーの共通の指示）
- `style.css`（6,574 行・1 枚）は**この作業では割らない**。セレクタは `check-css.mjs` が見ているので、id や class を変えない
