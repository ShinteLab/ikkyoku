# app: 棋譜を読む（貼り付け・URL・再読み込み・自動更新）

**`StudyService.LoadKifu` / `LoadKifuURL` / `ReloadKifu` / `FollowKifu`・`kifufetch.go` を触るときに読む。** `app/AGENTS.md` から分けた**制約**（「⚠️ …しないこと」）で、
⚠️ **自動では読まれないので、触る前に必ずここを開くこと**（索引は `app/AGENTS.md`）。

## 棋譜を読む（`StudyService.LoadKifu`）

- ⚠️ **棋譜を読んでも `PositionService`（訂正タブ）は触らない。** 撮った局面を
  消してしまうと、貼り付けたのが誤りだったときに戻る先が無くなる
- **指し手は全て載せるが、見ているのは開始局面**（2026-08-18 に最終手から変えた）。
  ⚠️ **最終手に置かないこと** —— 棋譜を読むのは**この対局を初手から解析するため**で、
  **連続解析の始点は「今どこを見ているか」**（`batchFrom`）なので、最終手に置くと
  **押す前に必ず開始局面まで戻る操作が要る**。先まで見たいときは盤の右の手順リストか
  評価値グラフで飛べばよい（`GoTo`。**手順は 1 手も消えない**）
- ⚠️ **取り直し（`ReloadKifu`）でも見ている位置は動かない**（2026-08-19）。
  読み込んだ直後は開始局面なので、**そのまま押しても開始局面のまま**。
  ⚠️ **`ReloadKifu` 側を「最後まで進める」に変えて辻褄を合わせないこと** ——
  **どこを見ているかはユーザーが選んだ状態**で、取り直しは
  「URL の側を正にする」操作でしかない。中継の最新手を見たいときは
  十字キーの下か手順リストで移る
- ⚠️ **途中で止まっても成功として扱う**（設計原則3）。読めなくなった手より前は
  正しいので、そこまでの局面は解析できる。理由は `KifuLoad.Note` に出し、
  **フロントで「note が空でない＝エラー」にしないこと**
- **KIF の読み取りも指し手 → USI の変換も `core/kifu`**（`Parse` / `DecodeMoves` /
  `StartSFEN`）。**ikkyoku にもフロントにも書かない** —— 将棋の**仕様**は core に一本化する。
  ikkyoku 側（`position.FromKIF`）がやるのは「読めた手を 1 手ずつ `Study` に指させる」
  というアプリ側の組み立てだけで、**合法性の判定は `Study.Play`（＝ `legal`）が持つ**
  ので、壊れた棋譜はそこで止まる
- ⚠️ **変化（`変化：N手`）は `core/kifu.Parse` が未対応**なので本譜だけが載る。
  分岐ツリーが入るまではこのまま（木の形は core で決める）
- **盤面図（BOD）つきの KIF も読める**（2026-09-16。`core/kifu/bod.go`）。途中局面から
  始まる棋譜は手合割ではなく盤面図が根になる。⚠️ **盤面図があるなら 0 手でも通す**
  （`position.FromKIF`）

## URL から取る（`kifufetch.go` → `kicho`）

`StudyService.LoadKifuURL` が取ってきて、あとは貼り付けと同じ経路に合流する
（**読み込んだあとの処理を 2 つに分けない**）。実測で
`http://live.shogi.or.jp/oui/kifu/67/oui202607290101.kif`（王位戦）が
151 手そのまま載ることを確認済み。

- ⚠️ **取得はフロントではなく Go 側。** webview の `fetch` は CORS で弾かれるうえ、
  **中継の .kif は Shift_JIS** なので、どのみちブラウザ側では読めない
- ⚠️ **文字コードは中身から判別する**（UTF-8 として妥当ならそのまま、駄目なら Shift_JIS）。
  **UTF-8 決め打ちにしないこと** —— 対局者名が化けるだけでなく、
  **漢数字が壊れて指し手が 1 手も読めなくなる**。何として読んだかは画面に出す
- ⚠️ **http / https 以外は受けない。** `file://` を通すと URL 欄から手元のファイルを
  読めてしまう（ファイルの読み込みは口として別に作るもの）
- ⚠️ **HTML が返ってきたら、そこに書かれた .kif を辿る**（2026-09-04。
  `scrape.KifURLFromHTML`。それまでは「棋譜ではない」と断っていた）。
  **これが無いと、棚から解析タブへ送った中継棋譜を「再読み込み」で追えない** ——
  連盟の中継の `source_url` は**中継ページ（HTML）の URL** だから。
  ⚠️ **ページから対局内容を読み取るわけではない**（取り込むのは .kif の原本）
- ⚠️ **辿った先ではなく、指定された URL を覚えること**（kicho の `source_url` と
  同じ扱い）。中継ページの `KIF_FILE_NAME` が一次情報で、**.kif のパスは変わりうる**
- **上限 4MiB・タイムアウト 20 秒。** 棋譜 1 局は数十 KB なので、
  これで足りないのは相手が居ないときだけ
- ⚠️ **中身の解釈は `kicho/scrape` に寄せてある**（2026-09-04 に `ikkyoku/kifuweb` を
  畳んだ）。文字コードの判別（`DecodeKIF`）・上限つきの読み取り（`ReadLimited`）・
  HTML から .kif を辿る（`LooksLikeHTML` / `KifURLFromHTML`）はどれも向こうの実装。
  ikkyoku 側に残っているのは http/https の制限と HTTP の取得だけ
- ⚠️ **`kicho.Library` を経由していない。** あちらは棋譜データベースを開けていないと
  使えないが、**URL から棋譜を読むのは棚に依らない操作**（設計原則3）。
  **`KifuService` 経由に書き換えないこと** —— DB が壊れると貼った棋譜も読めなくなる

### 再読み込み（`StudyService.ReloadKifu`）— **2026-08-13**

**同じ URL を読み直して、URL の側を正にする**（解析タブの**手順の見出し**の
**「手順」の真横にある更新アイコン**。2026-08-15 に「再読み込み」の文字ボタンから
変えた）。中継の .kif は 1 手進むたびに書き換わるので、**取り直せること
自体が「本譜は URL が更新し続ける」という一番よくある使い方の前提**
（`TODO.md` の「本譜のロック」）。

```
                      一致している範囲 │ 食い違ったところから先
今の手順   ７六歩 ３四歩 ２六歩 ８四歩 │ ５六歩（自分で指した）
URL の側   ７六歩 ３四歩 ２六歩 ８四歩 │ ６八銀 …
評価値     残す   残す   残す   残す   │ 捨てる
```

- ⚠️ **入力タブから読み直させないこと。** あちらは `LoadKifu` が根ごと入れ替える
  ので、**評価値が全部消える**（同じ URL を読んでも別の対局として扱われる）。
  取り直しの口を別に立てているのはそのため
- ⚠️ **解析結果はそのまま残す**（これがこの口の理由そのもの）。捨てるのは
  **食い違ったところから先だけ**で、根が違えば（＝別の対局）全部捨てる
- ⚠️ **食い違いが無ければ `evalStore.dropAfter` を呼ばないこと。** あれは世代
  （epoch）を進めるので、**走っている解析の途中経過まで捨てる** ——
  1 手進むたびに押す使い方では毎回それが起きる
- ⚠️ **見ている位置は動かさない**（2026-08-19。**取り直す前に選んでいた手が
  そのまま選択状態で残る**）。据え直しでは節点が 1 つも消えないので、
  行き先は必ず生きている。⚠️ **最後の手を見ていたときも進めないこと** ——
  以前は「伸びた先の最後まで進める」だったが、その判定は**深さ**
  （`Ply() >= len(MainLine())`）でしか見ておらず、**枝は本譜より深くなり得る**ぶん
  「最後の手」と誤判定して、**枝を見ている最中に取り直すと本譜の終わりへ
  飛ばされていた**（実測で踏んだ）。⚠️ **「深さではなく本譜の最終手か」で
  直す形にも戻さないこと** —— 中継の最新手へ移るのは 1 操作
  （十字キーの下・手順リスト）で、**勝手に飛ぶほうが取り返しがつかない**
- ⚠️ **今は「捨てる」で済んでいるが、それは分岐ツリーがまだ無いから。**
  木が入ったら**捨てるのではなく別の枝として残す**ことになる。
  **直す場所は `mergeReloadLocked` の 1 か所**にしてある
- ⚠️ **取れなかった / 読めなかったときは今の手順を壊さない**（組み立てが通って
  から入れ替える）。中継が落ちても検討は続けられる
- ⚠️ **ボタンを出す条件は `StudyState.SourceURL`**（URL から読んだときだけ埋まる）。
  **入力タブの URL 欄を見ないこと** —— 欄はいつでも打ち換えられるので、
  **今の手順がどこから来たか**とは別物。⚠️ **根を入れ替えたら捨てること**
  （撮った局面・貼り付け・新規対局には取り直す先が無い）
- ⚠️ **置き場所は「手順」の真横**（2026-08-15）。**取り直す相手はその手順**なので、
  見出しの隣に置いて位置で対象を示す（連続解析を手順の見出しの行へ移したのと同じ）。
  右へ寄るのは連続解析のボタンだけ（CSS の `margin-left: auto`。⚠️ **`.field-label`
  側に `margin-right: auto` を戻さないこと** —— 見出しの直後で空くと、間に
  アイコンが挟まらない）
- ⚠️ **アイコンだけなので、意味は `aria-label` と `title` が持つ。**
  ⚠️ **`title` を空にしないこと**（文字が無いぶん、何のボタンかはこれでしか読めない）
- ⚠️ **`display: flex` は `hidden` に勝つ。** 打ち消し（`.icon-btn[hidden]`）を
  落とすと、**撮った局面でも取り直しのアイコンが出る**（押しても取り直す先が無い）。
  `<shogi-board hidden>` で踏んだのと同じ話
- **取り直している最中はアイコンを回す。** 文字が無くなったぶん、
  **押した手応えがアイコンにしか出せない**（理由は下の行にも出るが、目はボタンを見ている）
- **差し替えが起きたら文字で出す**（`KifuLoad.Note`）。自分で指した手が消えるので、
  **黙って済ませない**

### 自動更新（`StudyService.FollowKifu` / `SetKifuFollow`）— **2026-09-26**

**再読み込みを一定の間隔（既定 5 分）で自動でやり、最新手を見ていれば新しい手へ
付いていく**（手順の見出しの「再読み込み」の隣の電波のアイコン。入切のトグル）。
`TODO.md`「本譜のロック」の**「本譜が伸びるたびに追いつく（自動）」**がこれ。

```
フロント（持ち主の窓・解析タブを開いているあいだ）── n 分ごと ──> FollowKifu(advance)
                                                            │
      取り直し（ReloadKifu と同じ reloadKifu）── 据え直す直前に「先端を見ていたか」
                                                            └─> 見ていたら新しい先端へ GoTo
```

- ⚠️ **付いていくのは「本譜の先端を見ていたとき」だけ**（`FollowAuto` と同じ
  `tail -f` の約束）。戻って読んでいるなら動かさない。⚠️ **判定は据え直す直前**
  （ロックの中）—— 取りに行く前に見ると、取っているあいだに人が押した手順と食い違う。
  ⚠️ **フロントで先端かどうかを判定しないこと**
- ⚠️ **`ReloadKifu`（手で押す再読み込み）は今までどおり動かさない**。
  付いていくのは**人が自動更新を入れたとき**だけ（「今の局面が見たい」を勝手に決めない、
  の線引きは変えていない。入れること自体が「付いていきたい」の意思表示）
- ⚠️ **入切は Go 側が持つ**（`StudyState.KifuFollow`）。**切り離した窓でも同じ
  入切が見える**ようにするため。⚠️ **間隔を刻むのはフロント**（`sidepane.ts` の
  `syncFollow`）—— 連続解析が走っているかを知っているのがそちらだけなので
- ⚠️ **刻むのは持ち主の窓だけ・解析タブに居るあいだだけ**。前者は同じ URL を
  2 倍叩かないため、後者は**付いていった先で連続モードの自動解析が起き、
  見ていないタブのためにエンジンが起動する**のを避けるため。戻ったらすぐ 1 回取り直す
- ⚠️ **連続解析（と自動で指し継ぐ）の最中は `advance` を偽にする**（取り直すだけ）。
  あちらが局面を 1 手ずつ動かしているので、横から動かすと解析を打ち切り合う
- **一度に 2 手以上来て付いていったら、途中の手も解析してから最新手へ戻る**
  （2026-10-02。`sidepane.ts` の `startCatchUp`）。間隔が分単位なので数手まとめて
  来るのは普通にあり、付いていくだけだと**途中の手の評価値が抜ける**。
  - ⚠️ **途中の手は設定に依らず 5 秒**（`catchUpSeconds`。ユーザー指定）。
    **最新手は今までどおり連続モードの自動解析**（設定の秒数。「無制限」もそのまま）
  - ⚠️ **中身は連続解析**（`batchStep` が辿り、記録は普段の `recordEval`）。
    **追いつき専用の道を作らないこと**
  - ⚠️ **付いていかなかったとき・連続モードが切ってあるときはやらない**
    （前者は読んでいる盤を動かすことになり、後者は最新手も解析しない設定）
  - ⚠️ **止めても・失敗しても最新手へ戻る**（`finishRun` → `backToTip`。人が止めたときは
    戻った最新手を解析しない）。**途中の手に置いたままだと先端を見ていないことになり、
    以後の自動更新が付いていかなくなる**
  - ⚠️ **追いつきのあいだは取りに行かない**（`followDeferred`。戻ってから 1 回やる）——
    取ると付いていけないまま手が伸び、**戻る先が古い最新手になる**
- ⚠️ **取っているあいだに別の局面へ入れ替わったら据えない**（`reloadKifu` が
  `sourceURL` を見比べる）。**自動更新は人が見ていないところで走る**ので、
  これが無いと、採ったばかりの局面が古い取得で**木ごと入れ替わって消える**
  （根が違うので `mergeReloadLocked` が別の対局として扱う）
- **終局まで載ったら自動で切る**（`RecordEnd`。投了のあとは伸びない）
- ⚠️ **`sourceURL` を捨てるところでは必ず一緒に切ること**（取り直す先が無いのに
  「自動更新中」と出る）。⚠️ **設定ファイルにも控えにも持たない**（その場かぎり）
- **手が来ていなければ黙る**（定期的に通るので、毎回出すと他の理由を押し流す）。
  来たとき・断りがあるときだけ手順の下に 1 行出す（`KifuLoad.Added` / `Followed`）
- ⚠️ **盤の脇の「中継を追う」（Phase 6。画面を撮って手を起こす）とは別物**
- **間隔は設定ファイルだけで変える**（`config.json` の `kifuFollowMinutes`。分。
  既定 5 分・解決は `Config.KifuFollowInterval`）。⚠️ **画面に分数の欄を置かないこと**
  （2026-09-26 のユーザー判断。アイコンの近くにコントロールを増やさない）。
  最初は 30 秒だったが「少し速い」で 5 分にした。⚠️ **読むのは起動時と
  設定が変わったとき**なので、手で書き換えたら起動し直す
