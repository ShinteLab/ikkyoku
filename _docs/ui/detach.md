# ペインを別ウィンドウへ切り離す（`graphscreen.ts` / `studyscreen.ts`）

**盤の大きさに依存しない大きさで見たい**というのが切り離しの目的。
⚠️ **畳む（高さ 0 / 幅 0）とは別の状態。**
⚠️ **ここは画面の話。** Go 側の制約は `CLAUDE.md` と各パッケージの CLAUDE.md にある。
⚠️ **ここに書いてある ⚠️ は「実際に踏んだ」もの。要約したり消したりしないこと。**

##### 別ウィンドウへ切り離す（**2026-09-08**）

**ペインのままだと盤の大きさに効く**（`--board-size` がグラフの高さを引いている）
ので、**盤を好きな大きさにしたい**という要求には畳むだけでは足りない。
そこで**窓へ出せる**ようにした（`?window=evalgraph`）。

| | 入口 |
|---|---|
| 切り離す | **見出しの行の右端**（`#eval-graph-detach`） |
| 戻す | **同じ場所**（切り離した窓の「ドックに戻す」）、または**窓を閉じる** |

⚠️ **畳む（高さ 0）とは別の状態。** 畳むのは「今は見ない」、切り離しは
「**別の窓で見る**」。**畳んだ高さは覚えたまま**なので、戻せば元の高さで出る。

- ⚠️ **状態を持っているのは設定**（`Config.EvalGraphDetached`）。**起動のたびに
  ドックへ戻さない** —— 枠の表示（残さない）とは扱いが違い、これは
  **画面の組み方の好み**だから
- ⚠️ **切り替えは必ず `SettingsService.SetEvalGraphDetached` を通すこと。**
  窓を閉じる操作もここを通る（`registerGraphHooks`）ので、**入口が 2 つあっても
  設定と窓の状態が食い違わない**。窓を出し入れするのは
  `CaptureService.applyEvalGraphDetached`（**ウィンドウを持っているのはあちら**）
- ⚠️ **メイン画面へは `graph:detached` で知らせる。** 無いと、**窓を閉じて
  戻したのにペインが出てこない**（グラフがどこにも無くなる）
- ⚠️ **起動直後の形は設定から読むこと**（`showSettings`）。Go 側は起動時にも
  `graph:detached` を出すが、**その時点でフロントはまだ購読していない**
- ⚠️ **切り離しているあいだ、ドック側の行は出さない**（同じ値を 2 か所に描かない）。
  取り直しも止める（`EvalPaneHandle.setActive`）—— 見えていない側まで取り直すと
  **イベント 1 回につき往復が 2 回**になる
- ⚠️ **描くものはドックと同じ**（`evalgraphpane.ts`）。**置き場所を変えただけで
  挙動が変わってはいけない**ので、取り直しの間引きまで共有してある
- ⚠️ **窓は破棄せず隠す**（枠と同じ）。破棄すると次に切り離すときに作り直しになり、
  **位置も大きさも失う**
- ⚠️ **`app.Run()` の前に `Show()` を呼んでも何も起きない**（2026-09-08 に踏んだ）。
  Wails の `WebviewWindow.Show` は `globalApplication.impl == nil` で**即 return** する。
  起動時の適用を `main()` の中に書いていたせいで、**設定は「切り離し」のままなのに
  窓が出ず、グラフがどこにも無い**という状態になった（戻す入口はその窓の中に
  あるので、**戻すこともできない**）。**出すのは窓自身の `WindowRuntimeReady`**
  （`registerGraphHooks`）。⚠️ **そこで `Focus()` は呼ばないこと** ——
  起動直後にメイン画面からフォーカスを奪う（ユーザーが押した結果ではない）
- ⚠️ **出せなかったらドックへ戻すこと**（設計原則3。`IsVisible()` で確かめる）。
  窓が出ないまま設定だけ「切り離し」で残ると、**グラフがどこにも無いうえ
  戻す入口も無い**
- ⚠️ **Frameless にしない。** 枠とメイン画面には理由がある（中継に重ねる透過窓 /
  タイトルバーのぶんを盤に返す）が、**これは普通のユーティリティ窓**。
  OS のタイトルバーがあれば移動・リサイズ・閉じるが全部ただで手に入る
- ⚠️ **`AlwaysOnTop` も付けない**（中継を覆う。メイン画面と同じ判断）
- ⚠️ **`maskWindows` に足すこと**（`captureservice.go`）。あちらに盤は無いが、
  **折れ線と目盛りは格子に似た直線の集まり**で、自動フィットの検出を汚す余地がある
- ⚠️ **盤の式から引く量も変わる**（`--eval-graph-pad`。**3 状態ある**）。
  切り離すと行ごと消えるので、畳んだとき（20px）とは別の値（**8px**。実測）

##### 盤の右の列も別ウィンドウへ切り離す（**2026-09-08**）

**評価値グラフと同じ形で、`.study-side` ごと窓へ出せる**（`?window=study`）。
**盤の大きさに依存しない大きさで見たい**というのが切り離しの目的で、
`--board-size` は右の列の幅（`--study-side-min`）を引いているので、
畳むだけでは「候補手も見たいが盤も大きくしたい」が成立しない。

| | 入口 |
|---|---|
| 切り離す | **解析の行の右端**（`#study-side-detach`） |
| 戻す | **同じ場所**（切り離した窓の「ドックに戻す」）、または**窓を閉じる** |

⚠️ **評価値グラフとは別の設定**（`Config.StudyPaneDetached`）。**1 つにまとめないこと**
—— 片方だけ切り離す使い方が普通。

- ⚠️ **切り離しても、ドック側のペインは隠れたまま生きている。** そのままだと
  **両方が連続モードで解析を起こし合う**（互いの解析を打ち切り続ける）ので、
  使われていない側は `SidePaneHandle.setActive(false)` で**自動解析をしない**。
  **この歯止めを外さないこと**
- ⚠️ **切り離しているあいだはタブを移ってもエンジンを手放さない。** 寿命を解析タブに
  紐づけているのは**そこに解析の面があるから**で、別ウィンドウに出しているなら
  **タブを移っても見えている**（止めると、見ている目の前で解析が消える）
- ⚠️ **畳んだ状態（`is-side-collapsed`）とは別の状態。** あちらは列を幅 0 へ縮めて
  **バーを右端に残す**（戻す口がバーの上にある）が、切り離しは**バーごと消す** ——
  戻す口は**その窓の中**なので、ここに残しても押す相手が居ない
- ⚠️ **`--study-side-min` を 0 にすること**（`applySideDetached`）。列が出ていないのに
  幅を予約したままだと、**そのぶん盤が小さいまま**になる
- ⚠️ **窓に見出しの行を作らないこと**（2026-09-09 に外した）。一番上に 1 行積むと
  **そのぶん候補手と手順の取り分が減る** —— 切り離すのは大きく見たいからなので、
  行を積むのは逆行する。「ドックに戻す」は**解析の行の右端**に入れてある
  （`SidePaneOptions.action`。⚠️ **ドック側には渡さない** —— 戻す相手が居ない）
- ⚠️ **出す/戻すは同じ場所に置くこと**（2026-09-09 にバーの上から移した）。
  **ペインの中の同じ行の右端**で、ドックしているときは「切り離す」（⧉
  `FiExternalLink`）、切り離した窓では「ドックに戻す」（⤡ `FiMinimize2`）。
  **どちらの状態でも探す場所が変わらない**のが要点で、**バーの上に戻さないこと**
  —— あちらは畳む/広げるための場所で、**切り離しは畳むのとは別の状態**
- ⚠️ **どちらもアイコンだけ。意味は `aria-label` と `title` が持つ**
  （文字が無いぶん、何のボタンかはこれでしか読めない。手順の「再読み込み」と同じ）。
  **2 つの窓で同じ絵にすること** —— どちらがどうだったかを覚える羽目になる

###### ⚠️ 「局面があるか」を他の要素の `hidden` から読まないこと

**2026-09-09 に踏んだ。** 切り離すと `.study-side` も `#eval-graph-row` も
**「切り離しているから」という別の理由で `hidden` になる**。片方の状態を
もう片方から読むと、**戻したときに「局面が無い」と誤読する。**

実際の症状: **解析の列を切り離していると、評価値グラフをドックへ戻しても
出てこない**（`--eval-graph-h` は戻るので**盤は縮む＝領域は動く**のに、
行が `hidden` のまま）。

**局面があるかどうかは `studyLoaded` の 1 つで持つこと**（`showStudy` が入れる）。
⚠️ **`studySide.hidden` や `studyStage.hidden` を代わりに読まない。**

###### 窓をまたぐ連動（**盤に効くもの**）

**ドックしているあいだはコールバックで直に渡している**ものが 3 つあり、
切り離すと届かなくなる。**フロントの `Events.Emit` で送る**（Go を経由して
`EmitEvent` → `dispatchEventToWindows` で**全部の窓へ**配られる）。

| イベント | 何のため |
|---|---|
| `study:hint` | 候補手を選んだときの**盤の矢印** |
| `study:scores` | **勝率バー**（盤の上にある） |
| `study:busy` | **連続解析の幕**（盤も触らせない） |
| `settings:changed` | 色や候補手の本数を切り離した窓で変えたとき（設定タブは別の窓） |

- ⚠️ **届かなくても壊れないこと**（設計原則3）。盤の矢印・勝率バー・幕が
  更新されなくなるだけで、**盤も手順も解析も動く**
- ⚠️ **ドックしているあいだは飛ばさない**（コールバックで足りる）。両方やると
  同じ値を 2 経路で描くことになる
