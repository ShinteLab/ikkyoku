# 画面の構成（ウィンドウ・タブ・イベント）

`main.ts` / `frame.ts` / `mainscreen.ts`。**どの面に何を出すか**と、
**撮ってから認識までの 2 段**の話。

⚠️ **ここは画面の話。** Go 側の制約は `CLAUDE.md` と各パッケージの CLAUDE.md にある。
⚠️ **ここに書いてある ⚠️ は「実際に踏んだ」もの。要約したり消したりしないこと。**

#### ⚠️ 撮ることと認識することを分ける（**イベントは 2 段**。2026-08-18）

**認識には数秒かかる。** 撮り終えてから認識まで終えて 1 回だけ知らせていた頃は、
**そのあいだ枠に「撮影中…」が出たままで、メイン画面は前の 1 枚を出したまま**だった。
つまり**待っている数秒のあいだ、今どの画像の話なのかが画面から読めない**
（撮れているのかどうかも分からず、撮り直しを誘発する）。

```
撮る ──> PNG 保存 ──capture:shot──> 枠: シャッターの合図 / メイン画面: 前に出て「認識中」
                        │
                        └─ 認識（数秒）──capture:done──> 認識結果で上書き
```

| イベント | 何が確定しているか | 誰が何をする |
|---|---|---|
| **`capture:shot`** | **撮れた**（PNG・サムネイル・パス） | 枠は `flash` + `playFlyout`、メイン画面は `showShot` |
| `capture:done` | **認識まで終わった**（`CaptureResult`） | メイン画面が `showResult` で上書き |

- ⚠️ **枠が見るのは `shot` のほう。** 合図の役目は「**今この 1 枚が撮れた**」を
  伝えることなので、認識を待って数秒遅れたら意味が無い
- ⚠️ **メイン画面を前に出すのも `shot` の時点**（`revealMain`）。以前は認識まで
  終えてから出していた。**撮影そのものは既に終わっている**ので、
  前に出たメイン画面が写り込むことはない
- ⚠️ **待たせる面は行き先と同じにする。** `showShot` が訂正タブを開き、
  **撮った画像を出して盤のところに「認識しています…」と書く**（`showBoard` の
  `busy`）。**「まだ撮っていません」と混ぜないこと** —— 撮った直後の数秒は盤が
  無いのが正常で、そこにそう出ると撮れていないように見える
- ⚠️ **前の 1 枚の片付けも `shot` でやる**（盤・駒台・警告・「認識詳細情報」・
  解析タブ）。**認識を待つあいだ古い結果が残っていると、撮った 1 枚のものに見える**
- **`CaptureShot` に認識結果は載せない**（まだ無い）。続きは `capture:done` が
  丸ごと持ってくる。⚠️ **どちらのペイロードも bindings に出ない**ので、
  **Go 側を変えたら `mainscreen.ts` / `frame.ts` の手書きの型も直すこと**

- メイン画面は **4 タブ**（入力 / 訂正 / 解析 / 設定。下記「タブの分け方」）。
  認識の記録は**訂正タブの盤の下・「この局面を解析する」の上**の折りたたみ
  「**認識詳細情報**」（旧デバッグタブ。2026-08-18 に盤の上から移した）。
  設定タブは
  「起動時に盤面を探す」「**駒の字**」「解析エンジン」「勝率の表示」
  「訂正盤面を suteme に登録する」（接続先・トークン）で、
  **変えたその場で保存する**（適用ボタンを置かない。押し忘れて反映されないほうが
  分かりにくい）。テキスト欄は `change`（確定時）で拾うので 1 文字ごとには書かない。
  警告・エラー・信頼度の低下が出ると「認識詳細情報」の見出しに点が付く（開けば消える）。
  信頼度を点の対象に含めているのは、**盤が映っていない画面を撮ると警告が 1 件も出ない
  ことがある**ため（局面の中身の話ではないので `warnings` には載らない）
- 「認識詳細情報」の「撮った画像」の見出しに**保存した PNG のファイル名**を出しており、
  押すと**フルパス**がクリップボードに入る。撮った PNG は suteme の学習データにも
  他のツールで開く対象にもなるので、パスを手で写す場面が多いため。表示がファイル名
  だけなのは保存先が毎回同じで区別が付くのは末尾の時刻だけだから。クリップボードは
  **Wails ランタイムの `Clipboard.SetText`** を使う（`navigator.clipboard` は
  secure context 前提で、カスタムスキーム配信のこの webview では当てにできない）
- その隣のボタンで**画像そのもの**をクリップボードに入れられる（チャットや棋譜ソフトへ
  直接貼る用）。**用途が違うので両方残すこと。** ランタイムのクリップボードは
  テキストしか扱えないため、こちらは Go 側（`CaptureService.CopyImage` →
  `native_windows.go`）で **Win32 の CF_DIB**（24bpp・無圧縮・ボトムアップ）を
  載せている。cgo は使わない（`native_windows.go` と同じ LazyProc 経由）。
  フロントから渡すのはパスで、**Go 側が保存済みの PNG を読み直す**（「直近の画像」を
  メモリに抱えないため。後から一覧を作ってどの 1 枚でもコピーできるようにもできる）
- **「認識詳細情報」は撮った画像に認識の矩形を重ねて出す**（`Result.Debug`。上記の表を参照）。
  盤面と判定した外枠・9x9 のマス割り・確信度の低いマスを描き、マスにホバーすると
  「マス名・採用した表記・確信度」が出る。トグルで消せる（画像そのものを見たいとき用）

  **描いた画像を Go 側から返していない。** サムネイルは既に等倍 PNG の base64 なので、
  描き込んだ 2 枚目を積むとイベントのペイロードが倍になる。座標だけを渡して
  SVG を重ねれば 81 マスで 10KB 程度で済み、ホバーもオン/オフも後から足せる。
  SVG の `viewBox` を入力画像の座標系そのものにし、`preserveAspectRatio="none"` で
  表示サイズへの換算を任せている（**`.thumbnail` に `width`/`height` を与えないこと**。
  `max-*` だけなら要素の箱が画像の描画領域と一致し、`inset: 0` の SVG がそのまま重なる）

  ⚠️ **盤は既定では 560px より大きくならない。** `<shogi-board>` の SVG は width 属性が
  固有サイズ（core/web の `CELL*9 + MARGIN*2`）で、CSS は `max-width: 100%` しか
  指定していないため、host を広げても伸びない。**`fluid` 属性を付けた盤だけが超えられる**
  （2026-08-12 に core/web へ足した。`:host([fluid]) svg { width: 100% }`）。
  ⚠️ **既定は変えていない** —— 既に置いている側（prokishi / suteme / core のデモ）で
  盤が勝手に伸びると、周りの余白の意味が変わるため。今 `fluid` を付けているのは
  **解析タブの盤だけ**（訂正タブは撮った画像と並べる面なので 560px のまま）。
  ⚠️ **付けていない盤に大きい箱を与えないこと** —— 絵が箱の中で中央寄せになり、
  重ねたグリッドがずれる


#### タブの分け方（**2026-08-10 に「盤面」1 枚から割った**）

以前は「盤面」タブ 1 枚の中で訂正モードをトグルしており、**同じ盤に「自由編集」と
「確定した局面」の 2 つの意味**が乗っていた。Phase 5 の「駒を動かすモード」を
足す前提で見ると持たないので、面ごと分けた。

**5 枚**（2026-09-04 に「棋譜」を足した）。

| タブ | 何をする面か | 盤 |
|---|---|---|
| 入力 | 局面を**取り込む**（**新規対局**・キャプチャ・**棋譜の貼り付け**・**中継から取得**） | 無し |
| **棋譜** | **棚（棋譜データベース）から探して解析へ送る** | 無し |
| 訂正 | 認識の誤りを**直して確定する** | **自由編集**（合法性を問わない・未決でよい） |
| 解析 | 確定局面から**手を進めて評価値を追う** | **合法手だけ**動かせる（クリック 2 回） |
| 設定 | 設定 | — |

⚠️ **棋譜タブは入力の隣**（`入力 / 棋譜 / 訂正 / 解析 / 設定`）。局面を持ってくる
口という点で入力タブと同じ側で、訂正・解析はその先の面。
⚠️ **取得・登録は棋譜タブに入れていない**（入力タブの中）—— **取り込む操作は
入力タブに集める**、という元の線引きのまま。棋譜タブは**探す**面。
⚠️ **タイトルバーがタブの行を兼ねている**ので、**ラベルは 2 文字に収めること。**

⚠️ **デバッグタブは無くなった**（2026-08-11）。中身は**訂正タブの中の折りたたみ
「認識詳細情報」**（`#debug-details`）に移した。**認識がどれくらい外したかを見るのは
訂正しながらやること**なので、タブを行き来する必要が無いほうがよい。

⚠️ **置き場所は盤の下・「この局面を解析する」の上**（2026-08-18。それまでは
盤の上＝警告のすぐ下）。**盤より上へ戻さないこと** —— 開くと**盤が下へ押される**ので、
中を見たいときに**盤が視界から消える**（そのために訂正タブをスクロールさせていた）。
下なら開いても**盤は動かず、下に伸びるだけ**。

```
┌─────────────┬──────────────────┐
│ 撮った画像       │   盤（560px 上限）        │
│（.capture-ref）  │   ＋ 駒台               │
└─────────────┴──────────────────┘
  認識詳細情報 ▸        ← 「撮った画像 + 盤」の幅いっぱい
  この局面を解析する（.edit-bar）
```

- ⚠️ **幅は「撮った画像 + 盤」の全体。** 一度**盤の左の列**（撮った画像の下）に
  置いてみて戻した —— 中身は**横に長い行**（推論器のパス・警告の文）と
  **等倍のサムネイル**なので、半分の幅では折り返しと縦スクロールだらけになる
- ⚠️ **中は「撮った画像 → 認識の情報」の順**（2026-08-18 に入れ替えた）。
  最初に見るのは**撮れているかどうか**で、確信度・推論器・警告はそれを見たあとの話。
  **畳んだ状態から開いて、まず画像が目に入るのが正しい**
- **既定で閉じる。** 開いた状態を既定にすると、すぐ上の原本の画像が押し縮められる
- **勝手に開かない。** 警告・エラー・信頼度の低下が出たら**見出しに点を出す**だけ
  （`markDebug`。開けば消える）。以前タブに点を付けていたのと同じ役割
- ⚠️ **撮った画像（`.capture-ref`）はこの折りたたみの外に置くこと。** 訂正は
  「原本を見ながら直す」作業なので、畳んだら消えるところに原本を置かない
  （折りたたみの中にも画像はあるが、あちらは**重ね表示つきの認識の記録**で用途が違う）

⚠️ **訂正タブと解析タブが別の局面を持っていること**（`PositionService` /
`StudyService`）は `CLAUDE.md` の「タブの分け方」。


#### `<shogi-board>` の配信（ファイルをコピーしない）

`core/web` は共有資産を `web.Assets`（embed）で公開している。ikkyoku は
`AssetOptions.Middleware` で `/shinte-web/` に流しているだけ（`shinteweb.go`）。
suteme の学習用サーバと同じパス・同じ方式。フロントは実行時に
`import("/shinte-web/shogi-board.js")` する（バンドル対象ではないので `@vite-ignore` 付き。
パスを変数に逃がしてあるのは tsc がリテラルを解決しようとするため）。

**npm 依存(`@shinte/web`)にはしていない。** private パッケージで `file:` 参照になり、
相対パスが git worktree で壊れるうえ node_modules 共有の問題も絡む。Go 側は既に core に
依存しているので、embed を配信するほうが単純で確実。

#### ⚠️ 駒文字フォントはドキュメント側に登録し直す必要がある

`<shogi-board>` は `@font-face`(ShogiSFEN) を **Shadow DOM 内の style にしか持っていない**が、
**Chromium は shadow root 内の `@font-face` を無視する**（フォントはドキュメント単位で解決される）。
そのままだと駒がラテン文字（`l`/`n`/`s`/`g`/`k`…、後手は 180 度回転）で描画される。
`mainscreen.ts` の `registerBoardFont()` が `font.js` の `FONT_DATA_URL` を
ドキュメントの `<style>` に登録し直して回避している（**フォントの実体は core のまま**）。
**本来は `core/web` 側で登録するのが筋なので、直ったらこの関数は消せる。**

同じ理由で、`shogi-board` に `hidden` を付けても消えない
（`:host { display: inline-block }` が UA の `display:none` に勝つ）。
外側から `shogi-board[hidden] { display: none }` を当てて打ち消している。
