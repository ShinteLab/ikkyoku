# app: 検討の控え（自動保存・棚と結ぶ・出どころの鍵・KIF にする）

**`studystore.go` / `studyrecord.go` / `studykey.go` / `studyexport.go`・`KifuService.SaveStudy` を触るときに読む。** `app/AGENTS.md` から分けた**制約**（「⚠️ …しないこと」）で、
⚠️ **自動では読まれないので、触る前に必ずここを開くこと**（索引は `app/AGENTS.md`）。

## 検討の控え（`StudyStore` / `StudyRecord`）— **2026-09-16。Step 1**

**再起動しても前回の続きから始められるように、木と評価値を丸ごと控える**
（`studyrecord.go` / `studystore.go`）。**1 セッション 1 ファイル**
（`Config.StudyDir` ＝ `ikkyoku/studies/<検討の id>.json`）。

⚠️ **控えはおまけ。書けなくても読めなくても解析は動くこと**（設計原則3）。
**エラーで起動を止めない。**

- ⚠️ **同一性を棋譜から借りないこと。** 棚（`kicho`）の主キーは
  `(source, source_id)` で、**中継を撮っている最中は行が作れない**。
  だから**自前の id を振り、`GameID` は空でよい**（棚と結ぶのは Step 2）
- ⚠️ **控えは棋譜ではない。交換形式にしないこと。** ikkyoku が自分で読み直すためだけの
  JSON で、配る形（KIF の `変化：N手`）は `core/kifu` が決める。core に木が入ったら
  KIF の書き出しは別経路で足す
- ⚠️ **`StudyService` に公開メソッドを生やさないこと。** Service の公開メソッドは
  **そのままフロントの API**（bindings）になる。控えの出し入れはフロントが
  呼ぶものではないので、`StudyStore` という別の型に持たせてある
- ⚠️ **根を入れ替えたら id を振り直すこと**（`newSessionLocked`）。
  **`evals.reset()` と必ず一緒に呼ぶ** —— 片方だけ動かすと、
  **前の対局の控えが上書きされる**か、**前の評価値が新しい木に残る**
- ⚠️ **id の後ろは時刻から作らないこと**（2026-09-16 にテストが落ちた）。
  ナノ秒を刻んでも、**続けて根を入れ替えれば同じ値になる**（Windows の時計は
  そこまで細かくない）。乱数で分ける
- ⚠️ **書くのは `evalStore.all()`**（`series` ではない）。あちらは**今の経路の
  点だけ**を折れ線にする描画用なので、それを控えると
  **開き直したときに枝の評価値だけ消えている**
- ⚠️ **`Game.Moves` は落とすこと。** **木のほうが本物**で、両方持つと
  どちらが本当か分からなくなるうえ、同じ手順を 2 回持つ。読んでいるのは
  ヘッダ（対局者・手合割）だけ
- ⚠️ **控えるのは `changed()` と `recordEval` の両方から**（`markDirty`）。
  評価値は `changed()` を通らないので、**片方だけだと「手は進めたが解析はまだ」の
  状態しか残らない**（＝ 評価値が 1 つも入っていない控え）
- ⚠️ **ロックの中で書かないこと。** 知らせるだけにして、間引く（3 秒）のも
  書くのも `StudyStore` の仕事 —— `analyze:info` は**深さが進むたびに、しかも
  エンジンの数だけ**届く
- ⚠️ **控えた時刻を除いて比べること。** 含めると毎回「変わった」ことになり、
  **何も変わっていなくてもディスクを叩き続ける**
- ⚠️ **`Restore` を `Start` より先に。** 逆にすると**復元する前の空の状態を
  控えに書く**
- ⚠️ **終了時にもう 1 回書くこと**（`Close`）。間引いている幅（3 秒）が
  そのまま「落ちたら失う幅」になる。⚠️ **解析を止めてから控えること** ——
  先に控えると、止める直前まで届いていた評価値が落ちる
- ⚠️ **人が始めた検討を控えで上書きしないこと**（`restoreSession` は
  `study != nil` なら断る）。黙って作業を捨てるのと同じ
- ⚠️ **読めない版は復元しないだけにすること**（起動は通る）
- ⚠️ **1 つしか試さない。** 読めなかったときに古いものへ遡ると、
  **何日も前の検討が黙って開く**（何が起きたのか画面から読めない）

### どのエンジンが出した値かは**ID で指す**（2026-09-16）

**控えに残すのは `EngineID` と凡例の名前だけ。** exe のパスも名乗った名前も
option も**設定（`Config.Engines`）にある**ので、**id で引けば済む**。

⚠️ **素性を写さないこと**（一度入れて外した）。写すと**同じことが 2 か所に載って
片方だけ古くなる** —— `DisplayName` と折れ線の色をフロントに持たせないのと同じ話。

⚠️ **それが成り立つ条件が「ID を使い回さないこと」**（`ikkyoku.NextEngineID`）。
以前は `engine-1` から空きを探していたので、**`engine-2` を消して別のエンジンを
足すとまた `engine-2`** になった。設定ファイルの中だけで通じればよかった頃は
それでよかったが、**控えが評価値をこの id で指す**ようになったので、使い回すと
**前のエンジンの評価値が別のエンジンのものとして読まれる。**

⚠️ **凡例の名前（`Label`）だけは写す。** 登録を消したあとでも**折れ線に名前が
要る**（生の id が凡例に並ぶと、どの線が何なのか読めない）。
**設定から引けるうちはそちらが勝つ**ので、これは引けなくなったときの控え。

### 控えるのは「木から引けないもの」だけ（`StudyEvalPoint`）

**点が持つのは `ID` / `CP` / `Mate` / `WinRate` / `Label` / `Depth` の 6 つ。**

⚠️ **手数も棋譜手数も指し手の表記も控えないこと**（2026-09-16 に落とした）。
**どれも同じ控えの中の木から引ける** —— `ID` が節点を指しているので、手数は
節点の手数、指し手は節点の表記そのもの。写すと**木は「７六歩」、点は「同歩」**の
ような食い違いが起こりうる。**復元で木から引き直す**（`evalStore.load` の `at`）。

⚠️ **木に無い節点の点は捨てること。** 描く先が無いので持っていても意味が無い。

⚠️ **`WinRate` と `Label` は計算し直さない。** これは木から引けるものではなく
**エンジンが出した答え**で、**点は「そのとき何と出たか」の記録** ——
あとでポナンザ定数や書式を変えても動かさない。

### 棚の棋譜と結ぶ（**2026-09-16。Step 2**）

**棋譜タブの「解析する」で前の検討の続きが開く。**

```
KifuService.SendToStudy(id)
   ├─ 控えがある → StudyStore.RestoreGame → adoptSession → graftKifu（棚の棋譜を据え直す）
   └─ 控えが無い → SendToStudyGame → loadKifuFrom（今までどおり）
```

- ⚠️ **`gameID` は `sourceURL` と同じ扱い**（`StudyService`）。**根を入れ替えたら
  捨てる** —— 撮った局面にも新規対局にも棚の行は無いので、残っていると
  **別の対局の控えを上書きする**
- ⚠️ **`sourceURL` とは別物。** あちらは**取り直す先**（URL）、こちらは
  **棚のどの行か**。URL から取っただけで棚に入れていない棋譜は前者だけ埋まる
- ⚠️ **開いたあと棚の棋譜を据え直すこと**（`graftKifu`）。棚の側が伸びていても
  **枝と評価値を捨てない**（`ReloadKifu` と同じ規約を通す）。
  ⚠️ **据え直せなくても復元は成立している** —— 検討は開けているので、
  棋譜が読めなかったことだけを断って返す
- ⚠️ **`adoptSession` は `restoreSession` の門番を通らない。** あちらは起動時
  （人が始めた検討を上書きしない）、こちらは**人が「この棋譜を解析する」と
  言っている**ので入れ替えるのが正しい
- ⚠️ **セッションを入れ替える前に控えを書かせること**（`saveNow`）。
  **根を入れ替える口を足したら必ず呼ぶ** —— 間引きの幅（3 秒）のあいだに
  入れ替えると、**直前までの手と評価値が前のセッションから落ちる**。
  今呼んでいるのは `Adopt` / `loadKifuFrom` / `NewGame` / `Clear` /
  `ReloadKifu` / `graftKifu` / `adoptSession`。
  ⚠️ **ロックを取る前に呼ぶこと**（向こうが `sessionRecord` でロックを取る）
- ⚠️ **索引は一度だけ組むこと**（`StudyStore.index`）。棋譜タブの一覧は
  控えは 1 セッション 1 ファイルなので、**引くたびにディレクトリを舐めると
  「解析する」を押すたびに待たされる**。以後は書いたときに足すだけ（`remember`）
- ⚠️ **同じ棋譜の控えが複数あったら後から書いたほうが勝つ**（`list` が古い順)。
  据え直しで根が変わると新しいセッションになるので、これは起こりうる
- ⚠️ **一覧に「検討あり」の印を出さないこと**（2026-09-16 に入れて外した）。
  **ほとんどの棋譜は一度は開く**ので、印を付けると**全部に付いて情報量がゼロ**に
  なる。⚠️ **一覧の行に「たいてい真になる印」を足さないこと**
- ⚠️ **控えを繋がなくても棚も解析も動くこと**（`KifuService.Store` が nil 可）。
  毎回まっさらに始まるだけ

### 出どころの鍵（**2026-09-26**。`studykey.go`）

**棋譜タブに入れる前の検討を、同じ棋譜にあとから結ぶ手掛かり。** 控えに
`StudyRecord.SourceKey` として書き、`StudyStore` が鍵 → 一番新しい控えの索引を持つ。

| 口 | 鍵 | 何をする |
|---|---|---|
| `KifuService.SendToStudyGame`（中継カード・棋譜タブの「解析する」の控えが無いとき） | `sourceKeyOf(source, source_id)` | 控えがあれば**続きから開いて据え直す**。行の id があれば**そこで結ぶ** |
| `StudyService.LoadKifu`（貼り付けの「解析する」） | `pasteKeyOf(本文)` | 同上（据え直しまで） |
| `KifuService.Save` / `ImportURL` | `sourceKeyOf(返った行)` | その控えに**棚の棋譜 id を書き足す** |
| `KifuService.ImportKIF`（貼り付けの「棋譜に登録する」） | `pasteKeyOf(本文)` | 同上 |

- ⚠️ **開き直しの据え直しは `graftKifu`**（棋譜タブから開くときと同じ規約）。
  **中継が伸びていても枝と評価値を捨てない。** 据え直せなくても開けたことは成功
- ⚠️ **結ぶ相手が今の検討なら今の検討に**（`StudyService.linkGame` → すぐ `saveNow`。
  書かないと索引に載らず、直後に棋譜タブから開いても続きが出ない）。
  **そうでなければ控えのファイルを書き直す**（`StudyStore.LinkGame`）。
  ⚠️ **今開いている検討のファイルは書き直さないこと**（次の自動保存と上書きし合う）
- ⚠️ **既に別の棋譜と結んでいる控えは移さない**（前の行から開けなくなる）
- ⚠️ **索引で引く前に今の検討を書かせること**（`restoreIndexed` の `saveNow`）。
  **今開いている検討をもう一度開く**（カードの「解析する」を押し直す）と、
  間引きの幅（3 秒）だけ古い控えで今の検討を上書きする
- ⚠️ **`sourceKey` は `sourceURL` と同じところで捨てる**（撮った局面・新規対局に
  残ると、別の棋譜の控えと結ばれる）
- ⚠️ **貼り付けの鍵は本文のハッシュで、揃えるのは改行コードと前後の空白だけ。**
  中身を解釈して揃えないこと（揃え方を間違えると別の棋譜を同じ検討に結ぶ）
- ⚠️ **貼り付けは「登録してから貼って解析」だと結ばれない**（棋譜タブの行の
  id を貼り付けからは知りようがない）。**その順なら棋譜タブの「解析する」から開けば
  そこで結ばれる**
- ⚠️ **結べなくても保存・登録は成功のまま**（設計原則3）
- 回帰テストは `studykey_test.go`

### 棚へ入れる（**2026-09-16。Step 3**）

⚠️ **画面からは外した**（2026-09-26。手順の見出しの「棋譜に登録」のアイコン）。
**終局してから入れる**使い方で、しかも「再読み込み」の隣で押し間違える。
代わりは上の「出どころの鍵」。**Go 側は残してある**（撮った局面から始めた検討を
棚に入れる口がこれしか無い）。以下は入れた当時の記録。

**`KifuService.SaveStudy`**（解析タブの手順の見出しの「棚に登録する」。**今は画面に無い**）。
本譜を KIF にして（`StudyService.exportKIF`）`ImportKIF` へ渡し、返った id を
検討に結ぶ（`setGameID`）。

- ⚠️ **KIF の組み立てを ikkyoku に書かないこと。** ヘッダの順も指し手の桁も
  `core/kifu` の担当で、ここがやるのは**木から手を並べて渡す**ところまで
  （`kifu.FormatMoves` が `Name` / `FromX` / `FromY` を返す）
- ⚠️ **根が手合割の初期局面と一致しないなら盤面図で書くこと**（`doc.Start`）。
  **黙って平手として出さない** —— 開き直すと**平手の初形に手順だけが乗った
  別の対局**になり、**棋譜としては通るので画面では気づけない**。
  ⚠️ **両方は書かない**（`kifu.Document.String` が盤面図を優先する）。
  ⚠️ **手数は戻らない**（盤面図に欄が無い）—— 局面と手順は正しい。
  ⚠️ **0 手の検討も入れられること**（`position.FromKIF` が盤面図つきなら通す）——
  まだ 1 手も指していない検討は普通にあり、断ると**自分で書いた棋譜を自分で開けない**
- ⚠️ **表記にできなかった手があったら書き出さないこと**（`MoveText.OK`）。
  名前が空のまま並べると**手数だけ合っていて中身の無い棋譜**ができ、
  棚に入ってから気づくことになる
- ⚠️ **`ShowTime` を立てないこと。** この検討はどこからも時間を受け取っていないので、
  立てると `( 0:00/00:00:00)` が全手に並ぶ
- ⚠️ **既に結んでいるなら断ること。** `ImportKIF` は**毎回新しい棋譜として登録する**
  ので、通すと**同じ対局が棚に 2 件**並び、しかも**控えが新しいほうに移る**
  （前の行から開けなくなる）。ボタンも `StudyState.GameID` で隠す
- ⚠️ **結んだら控えを書かせること**（`saveNow`）。書かないと**索引に載らない**ので、
  **次の起動まで「解析する」が続きから開かない**
- ⚠️ **棚に入るのは本譜だけ**（`core/kifu` に木が無い）。**枝は控えに残る**
- ⚠️ **0 手でも入れられること。** **まだ 1 手も指していない検討は普通にある**
  （撮った 1 局面）ので、断ると**自分で書いた棋譜を自分で開けない**
  （`position.FromKIF` が盤面図つきなら 0 手を通す）
