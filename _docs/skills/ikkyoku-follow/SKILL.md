# 中継を追う — 調整とデバッグ

**なぜこういう作りなのか（`position.Connect` が芯・ふるい・訂正タブを通さない）は
`_docs/design-follow.md`（崩さないことの一覧はルートの `AGENTS.md`）。** ここは**実機で動かして詰めるとき**の手順。
⚠️ **制約（「…しないこと」）は各 AGENTS.md にある**（下の「触るときに読むもの」）。

⚠️ **足す前に `TODO.md`「4. 追従（Phase 6）の作りを見直す」を読むこと。**
今の作りは実機で踏んだものを 1 つずつ塞いだ継ぎ接ぎで、根っこ
（「追いつく」と「棋譜を起こす」が混ざっている）はまだ直していない。

## 1 周の流れ

```
フロント followTick（mainscreen.ts。1 周ずつ順番に。撮る間隔 250ms）
  └─> CaptureService.CaptureQuiet（_cmd/ikkyoku/captureservice.go）
        撮る(数ms)
        └─ gate: 前の 1 枚と盤の矩形の中だけ比べる(数ms)
             ├─ 変わっていない ─────────────> Skipped="unchanged"（読まない）
             ├─ まだ動いている ─────────────> Skipped="moving"（止まるのを待つ）
             └─ 変化して止まった
                  └─ detectGate: 盤を探す(0.15 秒)
                       ├─ マスタと合わない ─> OffBoard（読まない）
                       └─ 追っている盤 ───> 認識(2.1 秒)
  └─> StudyService.FollowAuto（app/followstudy.go）
        Rank（29µs）→ Connect（深さ 4。0.45ms）を追いつき切るまで繰り返す
        ├─ 足せた ─────> 手順に足す（推測なら橙の印）・録画に 1 枚
        └─ 足せない ───> 1 手も足せなかった周だけ 180 度回して試す（Flipped）
                          録画に x 始まりで 1 枚（上限あり）
```

## 症状から引く

| 症状 | まず疑うもの | 見る場所 |
|---|---|---|
| **1 手目から 1 手も進まない**（「盤面は変わっていません」で終わる） | **盤が上下逆に映っている**（後手で対局したゲーム画面）。平手の初形は上下対称なので**最初の 1 手で初めて分かる** | 追跡が止まり「盤が上下逆に映っているようです（逆向きなら … で繋がります）」と出る（`FollowAuto.Flipped`）。直し方は訂正タブの「目線」→ 撮り直して「この局面を解析する」 |
| **指したのに「変わっていません」が続く** | **ふるいが外している**（駒の面と盤の地色は明るさが近い） | ログの「変化が無いまま続いたので 1 枚読みます」の**いちばん大きかった差**。10 秒（`gateSkipMax`）で必ず 1 枚読むので、**それでも進まないならふるいではない** |
| **数手追えて、そこから無反応** | **遅れが `Connect` の 4 手を超えた**（二度と追いつけない。仕様） | 「見失っています」が出ているか（`followLostLimit` = 5 周）。**撮り直して「本譜に繋ぐ」で繋ぎ直す** |
| **長考のたびに「見失っています」** | **省いた周（`Skipped`）を見送りに数えている**（回帰） | `followLost` を数えている箇所。`Skipped` と `OffBoard` を先に見ているか |
| **大盤解説のあいだ重い** | `detectGate` が効いていない | ログの「別の盤と判断しました」が出ているか |
| **枠を動かしたら追えなくなった** | マスタが取り直されていない | ログの「枠が動いたので追う盤を取り直しました」 |
| **間違った手が入った** | 手の映り込みか、認識器が弱いか | 録画のその手の PNG（下記）。`-guess` なら推測で足した手。ログでその手の直前に**「隔たりが大きすぎます」**が出ていたら、`Rank` の差の付かない 1 位を採った（2026-10-05 に塞いだ。`Unsettled`）。**行き先に指した側の駒が読めていない手**は 2026-10-05 から採らない（`position.backed`）ので、それでも入ったなら行き先の先後まで読み違えている |
| **飛車が行って戻る（▲4八飛 → ▲2八飛）ような手が並び、そこから進まない** | 手が盤を覆った 1 枚から空想の手を足し、次の 1 枚で打ち消す手を足して、本当の手を落とした | 上と同じ。**録画の PNG を exe と同じ認識器で読み直すと、どのマスを読み違えたかが分かる**（下の「録画を読み直す」） |
| **「確かめています」のまま進まない** | 2 枚目が毎回違う答えを出している（手が動き続けている・読みが揺れている） | 2026-10-05 から 1 枚だけでは足さない（`followPending`）。ログの「候補を並べました」が周ごとに違う手を出していないか |
| **往復（4 手など）が手順から消えた** | **仕様**（同じ局面へ戻るので差分 0 に見える） | 手当ては撮る間隔を詰めて途中を拾うこと。**履歴から推測で補わない**（設計原則1） |

## 録画の読み方

**誤認識が起きたとき、「手が被ったのか、認識器が弱いのか」を切り分けるためのもの。**
**見送ったフレームは残らない**（1 秒に 4 枚撮るので、残すと埋まるうえ大半は空振り）。

`<captures>/follow/<開始時刻>/`（「追う」を押すたびに別のディレクトリ）:

| ファイル | いつ残るか | 何が分かるか |
|---|---|---|
| `master.png` | 「追う」を押したとき | **追いかける基準。** `recognize.Signature` は矩形と色しか持たないので、「なぜ別の盤だと判断したか」はこれと見比べる |
| `042-7g7f.png` | 手を足したとき（ぴったり一致） | その手を決めた画像。**手数は 0 詰め 3 桁**なので並びが手順の順になる |
| `042-7g7f-guess.png` | 推測で足したとき | 順番が決まらず行き先だけで進んだ手。**疑うならまずここ** |
| `030-P@5e.png` | 打つ手を足したとき | **`*` は `@` に置き換わる**（Windows のファイル名に `*` は使えない。2026-10-05 まで打つ手の画像は残っていなかった） |
| `x042-choices-1.png` | **繋げなかったとき**（上限 `followMissMax`） | **止まった瞬間の証拠。** 知りたいのは崩れ始めの数枚 |

### 録画を読み直す

**録画の PNG を exe と同じ認識器で読み直すと、その 1 枚を何と読んだかが分かる**（ログには候補の手しか出ない）。
配布した exe で運用中でも、録画とログさえあれば手元で切り分けられる。
`_work/` の下に `recognize.LoadDir(<設定の sutemeDataDir>)` → `Use()` → `recognize.FromImage` を回す
使い捨ての `main` を書き、`GOWORK=off go run ./_work/<名前> <PNG>...` で流す（`_work` は `./...` の対象外。
**終わったら消す** —— git に入れない）。⚠️ **認識器は exe と揃えること**（ログの「認識器を読み込みました」の
`mode` / `source`。`mode=dir` なら設定の `sutemeDataDir`、焼き込みなら同じ版の配布モデル）。

`<captures>/connect/<日付>/` は**手で繋いだ**（訂正タブの「本譜に繋ぐ」）ときの画像。
`-fixed` が付いていれば**人が認識を覆した**手。⚠️ **追従の録画とは別の場所**
（どちらの経路で決まった手かを読めるようにしてある）。

## ログの読み方

**ログは実行ファイルの隣の `ikkyoku_<日付>.log`**（`wails3 dev` なら `_cmd/ikkyoku/bin/`。
dev のときはターミナルにも出る）。追従だけ細かく見たいときは、同じ場所に
`ikkyoku-log.json` を置いてパッケージごとにレベルを上げる（書き方は `log/AGENTS.md`）。

**Go 側は「変わり目だけ」出す**（`noteQuiet`）。同じ行が続かないのは正常。

| ログ | 意味 |
|---|---|
| 追う盤を決めました | 「追う」を押した。`dir` が録画の場所 |
| 変わっていないので認識を省いています（追跡） | ふるい 1 段目で落ちている（正常） |
| 動いているので止まるのを待っています（追跡） | 変化はあったが静止待ち（`gateMovingMax` = 8 周で諦めて読む） |
| 別の盤が映っています（追跡・見送り） | 大盤など。**読んでいないので SFEN は空** |
| 盤が映っていません（追跡・見送り） | 読んだが盤が無い（解説・CM） |
| 変化が無いまま続いたので 1 枚読みます | `gateSkipMax` の保険。**いちばん大きかった差 / しきい値**が出る |
| 追跡を止めました | **撮った枚数 / 認識した枚数 / 省いた割合** |

## ふるいの定数を詰める

⚠️ **どれも当て推量**（2026-09-18 時点）。**実機の中継で上のログを見て詰めること。**

| 定数 | 値 | 場所 | 意味 |
|---|---|---|---|
| `gateChangedRatio` | 0.0015 | `_cmd/ikkyoku/captureservice.go` | 「変化した」と見なす点の割合（1 マス ≈ 1.2%） |
| `gateMovingMax` | 8 周 | 同 | 静止を待つ上限 |
| `gateSkipMax` | 40 周（約 10 秒） | 同 | 省き続けてよい上限 |
| `detectMissMax` | 8 | 同 | 盤が見つからない周が続いたら 1 枚は読む |
| `DiffSamples` / `DiffLevel` | 160 点 / 差 10 | `diff.go` | 見る点の数・明るさの差 |
| `followTickMs` | 250ms | `frontend/src/mainscreen.ts` | 撮る間隔 |
| `followStallMs` | 15 秒 | 同 | 1 周が返ってこないと見なすまで |
| `followLostLimit` | 5 周 | 同 | 「見失っています」と言い出すまで |
| `followCatchUp` | 12 手 | `app/followstudy.go` | 1 枚から足す手の上限 |

- **詰める材料**: 「追跡を止めました」の**省いた割合**（低すぎればふるいが素通し）と、
  保険で読んだときの**いちばん大きかった差**（しきい値にどれだけ届かなかったか）
- ⚠️ **しきい値を上げる方向は慎重に** —— **ふるいで落とした手は二度と戻らない**
  （1 枚余分に読むほうがずっと軽い）
- ⚠️ **見る点を粗くしない・明るさの差を大きくしない**（64 点 / 24 から直した）。
  駒の字は細い線なので、粗いと**駒が動いても差が出ない**
- ⚠️ **`followTickMs` と `followStallMs` を倍数で結ばない**（認識する周だけ 2 秒以上かかる）
- ⚠️ **`gateSkipMax` をしきい値の調整で代えない**（外したら永久に止まる作りに戻る）

**速さの実測は `references/measurements.md`。**
