# 追従の速さ（**実測**。2026-09-15）

⚠️ **再測しなくてよい。** 認識器（`suteme`）を入れ替えたときだけ測り直す。

## きっかけ

**ゲーム画面で試したら 4 手目までしか追えず、そこから 90 手まで無反応だった。**
認識も盤の検出も正しく、`conf=1.000` で SFEN も全部正解 ——
**遅かっただけ**で、しかも**1 周 1 手**しか足していなかった
（tick 1.2 秒 + 認識 2.1 秒で 1 周 3.3 秒。早指しに構造的に追いつけず、
遅れが `Connect` の 4 手を超えた時点で永久に復帰できなくなった）。

## 数字

| | 実測 |
|---|---|
| 認識 1 枚（盤を探す） | **2.1〜2.3 秒** |
| 認識 1 枚（盤の矩形を渡す） | 1.95 秒（**15% しか変わらない**） |
| 盤の検出だけ（`DetectRegion`） | 0.15 秒程度（認識の 15%） |
| 画素差分（`FrameDiff`） | 数ミリ秒 |
| `position.Rank` | 29µs |
| `position.Connect`（深さ 4） | 0.45ms |

⚠️ **重いのは盤の検出ではなく 81 マスの推論。** 速くするのは `suteme` 側の話で、
ikkyoku にできるのは次の 2 つだけ:

1. **1 枚から取れるだけ取る**（`FollowAuto` が同じ盤で追いつき切るまで足す。上限 `followCatchUp`）
2. **読む枚数を減らす**（画素差分と盤の有無のふるい。2026-09-18）

## ふるいを入れた効果の見積もり

- 撮る間隔を 1200ms → **250ms** にできた（ふるいは数ミリ秒なので）。
  **手が指されてから読み始めるまでの遅れが 1 手あたり約 1 秒縮む**
- 長考中の保険読み（`gateSkipMax`）は **10 秒に 1 枚 2.1 秒**。省く前（毎周 2.1 秒）とは桁が違う
- ⚠️ **`suteme` に盤の矩形を渡す案は却下済み**（15% しか縮まないうえ、録画中に
  画面の大きさが変わったときの振る舞いが難しくなる）。`detectGate` は**何も渡さない**
  （自分で探して、持っているマスタと突き合わせるだけ）
