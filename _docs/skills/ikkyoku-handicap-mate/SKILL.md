# 手合割（駒落ち）と詰将棋

**この 2 つは「盤にも駒台にも無い駒をどう読むか」という同じ問いへの、別の答え。**
ここはその全体像と手順の置き場で、⚠️ **制約（「…しないこと」）は各 AGENTS.md にある**
（触ったときに読まれる場所に無いと守れない）。

## 出発点: 駒台の逆算

撮った盤は**駒台が写っていない**ので、`position` は**駒数保存則で逆算**する
（40 枚 − 盤上 ＝ 駒台にあるはず）。**その逆算が訂正 UI の拠り所**で、
「足りない駒」の枠に出ている数がそれ。**未決が 1 枚でも残ると局面は確定しない**
（`SFEN()` が組み上がらない ＝ 解析タブへ渡せない）。

⚠️ **平手を撮ったときにしか成り立たない前提**がここにある。駒落ちの落とした駒も、
詰将棋で使わない駒も、**どちらの駒台にも無い**ので、逆算したままでは永久に確定しない。

## 3 通りの解釈（訂正タブのチェック 2 つ）

| | 盤にも駒台にも無い駒 | 立てるもの | 枠の見出し |
|---|---|---|---|
| 既定（平手） | どちらかの駒台にあるはず（未決） | — | 足りない駒（`Stock.Unassigned`） |
| **手合割** | **この対局に存在しない** | `HandsFixed` | 使わない駒（`Stock.Unused`） |
| **詰将棋** | **全部 玉方（後手）の持駒** | `MateProblem` | 足りない駒（残るのは攻方の玉だけ） |

⚠️ **手合割と詰将棋は排他**（`PositionService` が片方を外す）。
⚠️ **詰将棋は「操作」ではなく「属性」** —— 盤を直すたびに追随する
（1 枚外せばその駒が玉方の持駒に増え、攻方の駒を盤に置けばそのぶん減る）。
**保つ約束は「玉方 = 逆算した合計 − 攻方」**（`NormalizeMateHands` を 1 操作ごとに）。

## 入口（4 つ。行き先が違う）

| 入口 | 通る層 | 行き先 | 出てくる局面 |
|---|---|---|---|
| 新しく対局を始める（手合割） | 何も通らない | **解析タブ** | 手合割の初期局面（`core/kifu.StartSFEN`） |
| 手合割を「訂正タブで調整」 | 何も通らない | **訂正タブ** | 同上（`HandsFixed` 済み）。**独自ハンデはここから** |
| 詰将棋を並べる | 何も通らない | **訂正タブ** | 空の盤（`MateProblem` 済み・手番は攻方） |
| 撮る → チェックを入れる | 認識（`suteme`） | 訂正タブ | 撮った盤 + どちらかの解釈 |

**手合割の表は `core/kifu` が持っている**（香落ち・右香・角・飛車・飛香・二枚・三枚・
四枚・五枚・六枚・八枚・十枚）。⚠️ **ikkyoku にもフロントにも盤面を書かない。**
画面に出しているのは代表的な 6 つで、**option を足すだけで増える**。

## 側の呼び名

⚠️ **側も手番も局面も変わらない。呼び名だけ**（下手＝先手＝`b`、上手＝後手＝`w`）。

| | 平手 | 手合割 | 詰将棋 |
|---|---|---|---|
| 手番のボタン | 先手番 / 後手番 | 下手番 / 上手番 | 攻方番 / 玉方番（**押せない**） |
| 目線のボタン | 手前: 先手 | 手前: 下手 | 手前: 攻方（**押せない**） |

- ⚠️ **駒落ちは上手（後手）が初手**なので、始めた直後は**後手番**（`w` + 手数 1 は正当）
- ⚠️ **詰将棋は攻方＝先手固定・目線も先手固定**（どちらも決まっているので選ばせない）
- **呼び名の変換はフロントの `sideName` 1 か所**（Go 側は手合割の呼び名を知らない）

## 詰将棋を解く

**2 通りあり、要るエンジンが違う。**

| | 何をする | 使うエンジン |
|---|---|---|
| 通常の解析（「解析」） | 短手数なら詰みスコアで出る | **同梱エンジンだけ**（外部は攻方の玉が無いと無反応） |
| **詰み探索**（「詰み」） | `go mate` で解かせる。**長手数もこちら** | **詰将棋エンジン**（設定の「詰み」を付けた登録） |

**どのエンジンが何を返すかは `references/engines.md`。** ⚠️ **測ってあるので推測しないこと。**

- **攻方の玉が無くても合法手は出る**（`legal.Moves` は通る）ので、並べた詰将棋を
  解析タブでそのまま動かせる
- ⚠️ **詰将棋で意味があるのは「詰みかどうか」だけ。** 玉方が余り駒を全部持つので、
  **評価値は常に玉方の大優勢に出る**（数字を難易度として読まない）

### 詰将棋エンジンを繋ぐ手順

1. **詰将棋エンジンを入れる。** 確認済みは **KomoringHeights 1.1.0**
   （`user-normal-clang++-avx2.exe`。単体の exe で、評価関数も定跡も要らない）
2. 設定タブ →「エンジンを追加」→「参照…」で exe を選ぶ
3. その行の **「詰み」にチェック**。⚠️ **「解析に使う」とは独立した軸**
   （両方入れれば両方に使う。詰将棋エンジンは通常の `go` に `bestmove resign` を
   返すので、**通常解析に使うなら承知の上で**）
4. 解析タブで **「詰み」** を押す
5. 候補の本数（余詰）を増やすなら、**出てきた枠の見出しの「候補 n」**で変えて押し直す。
   ⚠️ **設定タブには MultiPV の欄が無い**（編集口を 2 つにしない。2026-08-15 の決定）

### 手元で直接試す（エンジンの素の応答を見る）

**アプリを通さずに 2 行で測れる。** 新しいエンジンを試すときはこれが一番速い。

```bash
cd D:/ShogiEngine/KomoringHeights
{ printf 'usi\nisready\nposition sfen 4k4/9/4P4/9/9/9/9/9/9 b G2r2b3g4s4n4l17p 1\ngo mate 5000\n'; sleep 10; printf 'quit\n'; } \
  | ./user-normal-clang++-avx2.exe 2>&1 | grep -E "^checkmate|^bestmove"
```

`4k4/9/4P4/…` は**攻方の玉が無い 1 手詰**（▲５二金打）。`checkmate G*5b` が返れば使える。
⚠️ **`setoption` は `isready` の前に送ること**（KomoringHeights の MultiPV は後から効かない）。
