## 評価値グラフの分かれ道の印と横軸（2026-09-16。ユーザーによる実機確認）

**棋譜を読み込んだ検討で確認した。** ⚠️ **撮った局面から始めた検討では
確かめていない**（中継が無くて材料が作れなかった）—— そちらは `checklist.md`。

- **枝を掘ると、その手数の下の帯に印が出ること** … 確認
- **投了図以下にも印が出ること** … 確認（⚠️ **最初は出なかった**。
  「子が 2 つ以上」でしか見ておらず、**投了図以下は子が 1 つ**だったため。
  **ユーザーの指摘で分かった** —— 中継を観ながら一番やることなのに、
  **一番印が欲しいそこで出ていなかった**）
- **本譜を見ているあいだ、横軸の「全て」が対局の終わりで止まること** … 確認
  （⚠️ **最初は投了図以下まで伸びていた**。115 手の棋譜が 131 手と出た。
  **これもユーザーの指摘** —— 90 手目から生やした枝は経路に入らないのに
  投了図以下だけ入る、という食い違いだった）

⚠️ **この 2 つの指摘から、裏にもっと悪い穴が見つかった**（`MainLine` /
`MainTip` も止まっていなかったので、**棚へ書き出す KIF に検討の手が対局の手
として載っていた**）。**見えている食い違いを「仕様です」で流さないこと** ——
**1 回目は実際そう答えて間違えた。**

## 中継を追う（Phase 6）の正常系（2026-09-15。ユーザーによる実機確認）

**実際の中継で「中継を追う」を押し、1 手指されたところで自動的に本譜が
1 手伸びることを確認した。** ⚠️ **ここまで来るのに実機で 5 回作り直している**ので、
下の 3 つは**根拠として引けるが、崩したら気づけない**ものでもある:

- **解析タブのまま手が増えること** … 確認。⚠️ **訂正タブへ飛ばない**
  （「訂正を挟むかどうかをこちらが決めない」という指摘から出た作り）
- **追跡中にメイン画面が前に出てこないこと** … 確認（`CaptureQuiet`）。
  出ると中継が隠れて**追う対象が見えなくなる**
- **押した瞬間の盤をマスタとして覚えられること** … 確認（`AnchorBoard`）。
  ⚠️ **本物の盤が映っている必要がある** —— 長考中に大盤解説が続くと**開始できない**
  （実機で待たされた。**今のところ他に手が無いので仕様**）

**大盤（解説用の盤）の出入り**（2026-09-15。ユーザーによる実機確認）:

- **大盤に切り替わっているあいだ手が増えないこと** … 確認。⚠️ **ここが効かないと
  解説が並べた変化をそのまま棋譜に足す**（盤面だけでは弾けないので、
  `recognize.Signature` で**同じ盤が映っているか**を別に見ている）
- **本物の盤に戻ったら自動で再開すること** … 確認。⚠️ **止まらないのが要点** ——
  大盤はすぐ戻るので**待つだけ**（止めると人が押し直すことになる）
- **盤が映っていないと「追う」を始められないこと** … 確認（`AnchorBoard`）。
  ⚠️ **これは実機で困った** —— 長考 + 大盤解説が続くと**試すことすらできない**。
  **マスタは要るので今のところ仕様**だが、代わりの案が出たら考え直す余地がある

**CM・解説が映っているあいだ手が増えないこと** … 確認（2026-09-15）。
⚠️ **大盤よけとは別の歯止め** —— あちらは「**将棋の盤ではあるが別の盤**」を弾き、
こちらは「**そもそも盤が読めない**」を弾く（`Readable`。一致度が落ちる）。
**次にすることが違う**ので 2 つに分けてある（待つ / 撮り直す）。

**推測で足した手の印（橙の丸）** … 確認（`Node.Guess`）。⚠️ **これが
「おかしくても進み、違うと思ったら人が戻る」の実体** —— 印が無いと
**どの手を疑えばいいのか分からない**ので、全部の手を見直すことになる。

⚠️ **まだ確認できていないこと**: 手数の食い違い・
しきい値（`fit` / `margin`）の実測（`checklist.md`）。

**ここまでに実機で潰した壊れ方**（同じ轍を踏まないための記録）:

| 症状 | 原因 |
|---|---|
| 0 手の根で「本譜に繋ぐ」が出ない | ボタンを `MainTip > 0` で出していた。**画像から追うときは必ず 0 手から始まる** |
| 誤認識だと「繋がりません」だけで進めない | `Connect`（到達できるか）を先に問うていた。**`Rank`（どれが一番合うか）が先** |
| 別の盤から戻ると無反応 | `StopBudget` で行き止まりにしていた（`fallbackFollow` が無かった） |
| 数分で黙って死ぬ | **見送りの `return` が次の 1 周の予約を飛ばしていた** |
| 動いているか読めない | 時刻・経過秒は**止まっても進む**ので証明にならない。**1 周ごとに打つ印**にした |

**GUI 自身のガイド枠を画面いっぱいに広げてキャプチャし、画像を目視して確認した。**
「画面全体を撮って目視で GUI の見た目を検証する」という手法自体は有効なので、今後も使える:

```powershell
Start-Process .\_cmd\ikkyoku\bin\ikkyoku.exe
# ガイド枠ウィンドウを画面いっぱいにドラッグ・リサイズしてから撮る
```

検証済み:

- **クライアント領域の透過** … 動作する。ABEMA の中継映像が枠の中に透けて見える
- **キャプチャ領域とガイド枠の一致** … 一致する。撮れた PNG に**赤いガイド枠は写り込まない**
  (`guideBorderPx` ぶんのオフセットが正しく効いている)
- **`Alt+S` の非フォーカス時の発火** … 動作する。フォアグラウンドが PowerShell の状態で
  発火してキャプチャが保存されることを確認（**この確認時は枠が出ていた**。
  2026-08-10 以降は枠が出ていないと撮れない）
- **操作パネルがガイド枠に重ならないこと** … 動作する(下記の修正後)

検証で見つかって直した不具合:

- **ガイド枠ウィンドウに `AlwaysOnTop` が無く、中継ウィンドウの後ろに回っていた。**
  中継の「上」に重ねて位置合わせをする道具なので必須。操作パネルにだけ付いていた
- **初回起動時、ガイド枠と操作パネルが両方 `WindowCentered` になり重なっていた。**
  重なるとパネルごと写り込む。`WindowRuntimeReady` で枠の位置を読み、パネルを枠の外へ
  退避させるようにした

#### 追加検証(Frameless 化・メイン画面の格上げ後)

**アプリを起動 → HWND から矩形を直接取得 → その矩形をスクリーンショットから切り出して
ピクセル値を調べる**、という手順で写り込みを厳密に確認した。目視より確実なので今後も使える
(検証用の PowerShell は使い捨てにしたが、`GetClientRect`+`ClientToScreen`+`GetDpiForWindow` を
呼ぶだけ)。撮った PNG の外周 2px をスキャンして赤(`#E93D3D` 系)が 0 個であることを確認している。

- **ツールバー・ガイド枠の写り込み** … 無し。四辺すべて内容のみ(`476x384`)
- **枠のクライアント矩形が Frameless でウィンドウ全体と一致すること** … 確認
  (メイン画面は `704x481` client / `720x520` window なのに対し、枠は `480x421`/`480x420`)
- ~~**起動直後は枠だけが見えること**~~ … **2026-08-10 に逆にした**（起動時に出るのは
  メイン画面で、枠はタイトルバーの「枠を表示」を押すまで出ない）。当時の確認結果なので**根拠に使わないこと**
- ~~**最初のキャプチャでメイン画面が出ること**~~ … 同上（メイン画面は起動時から出ている）。
  ⚠️ **枠の下に非重複で配置される**（`placeMainBesideFrame`）のは今も生きている
- **枠を閉じてもアプリが生き残ること** … 確認(`WM_CLOSE` を送ってもプロセス継続・枠は非表示)
- **メイン画面を閉じるとアプリが終了すること** … 確認
- **ウィンドウ位置・サイズの保存・復元** … 確認(枠を `300,200` へ動かして終了 → 保存値が
  `300,200` → 再起動でその位置に復元)。**これは以前「未検証」だった項目で、実際に壊れていた**
  (終了時に `Position()` を読んでいたため。`_docs/cmd-windows.md` の「ウィンドウ状態の永続化」参照)
- **`CGO_ENABLED=0` でのビルド** … 通る(PureGo 方針の維持を確認)
